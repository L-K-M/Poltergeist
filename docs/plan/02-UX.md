# 02 — UX specification

This chapter is the screen-by-screen contract for `app/poltergeist_app`. It
elaborates the decision log in [00-OVERVIEW.md](00-OVERVIEW.md) — especially
D11 (quiet chrome), D12 (performance budgets), D13 (single window), D14
(drag & drop), D16 (activity panel), D17 (editor seams), D20 (a11y/i18n),
D21 (command registry) — and never reopens it. Architecture wiring is 03;
bookmark schema is 04; sync preview UX is 05; editor screens are 06.

Two research sources drive the shapes below: Transmit 5 and ForkLift 4
feature studies, and the Séance UI deep-read (reusable modules and the
SEA-/SOL- debt list of what *not* to copy). Séance file paths cited here are
relative to `/home/user/Seance/app/seance_app` unless prefixed.

## 1. Window anatomy

One window (D13), owned by a `WorkspaceController`. Layout:

```
+---------------------------------------------------------------------------+
| titlebar / toolbar               (per-platform chrome, §11)               |
+-----------+------------------------------+--------------------------------+
| sidebar   | pane A                       | pane B                         |
| Devices   | [tab][tab][+]                | [tab][tab][+]                  |
| Connect-  | [path bar............][view] | [path bar...........][view]    |
|  ions     | [listing                   ] | [listing                    ]  |
| Favorites | [                          ] | [                           ]  |
|  (groups) | [                          ] | [                           ]  |
|           | [pane footer: counts, free ] | [pane footer                ]  |
+-----------+------------------------------+--------------------------------+
| activity panel (optional, D16): task rows | History tab | throttle        |
+---------------------------------------------------------------------------+
| status bar: selection summary · sync-browse chip · transfer chip · limit  |
+---------------------------------------------------------------------------+
```

Regions and their collapse behavior:

| Region | Collapsible | How |
|---|---|---|
| Sidebar | yes | `view.toggleSidebar`; below stage-1 width it auto-collapses to an overlay drawer |
| Pane B | yes | `view.toggleSecondPane` (⇧⌘D); hidden pane state is remembered (§3) |
| Activity panel | yes | `view.toggleActivityPanel`; collapsed state = status-bar transfer chip only |
| Status bar | no | always visible; it is the honesty strip |

Three draggable splitters: sidebar↔panes, pane A↔pane B, panes↔activity
panel. All three reuse Séance's `AdaptivePaneLayout` pattern
(`lib/ui/adaptive_shell.dart`): pure allocation math in a Flutter-free
function, keyed handles, drag-start adoption of rendered widths. Handles are
focusable and keyboard-resizable (arrow keys, 16 px steps) — fixing Séance's
SOL-060/SOL-064 instead of copying them.

**Staged responsive collapse — never a single cliff** (Séance's SEA-015
lesson). Stages, evaluated on window content width:

| Stage | Width | Behavior |
|---|---|---|
| 0 | ≥ 1080 px | sidebar + both panes + optional activity panel |
| 1 | 680–1079 px | sidebar auto-collapses to an overlay drawer (toolbar button + shortcut still open it); both panes remain |
| 2 | < 680 px | pane B auto-hides (remembered, §3); single pane + drawer sidebar |

Rules: exactly one region changes per threshold; auto-collapsed regions
restore automatically on regrow, but a region the *user* hid stays hidden
(user intent outranks responsive logic). Stage 2 doubles as the mobile
posture required by D29.

**Persistence** (fixing SEA-018/SOL-062): persist sidebar width, pane A:B
split **as a ratio**, activity-panel height, activity-panel and sidebar
visibility, and window geometry. Restore geometry clamped to the current
work area. Defaults: window 1180×760 centered, minimum 720×480; sidebar
240 px (min 200, max 320); pane ratio 0.5; activity panel 200 px
(min 120 px, max 50% of window height).

**Status bar** (left to right): active-pane selection summary
(`128 items, 3 selected — 42.1 MB`), sync-browsing chip (§7, only when
enabled), bandwidth-limit chip (§6, only when limiting), transfer summary
chip (`↑ 2.3 MB/s · 3 tasks` with a mini progress ring; click toggles the
activity panel; error badge count when tasks failed). Nothing in the status
bar is the *only* representation of anything — it summarizes panes and the
queue, which own the detail.

## 2. Panes — the browser view

Each pane hosts a tab strip (§3); each tab renders one *location*. Locations
are a sealed type in `poltergeist_core` (03 owns the wiring):

```dart
sealed class PaneLocation { const PaneLocation(); }

class LocalLocation extends PaneLocation {
  const LocalLocation(this.path);
  final String path;
}

class RemoteLocation extends PaneLocation {
  const RemoteLocation(this.serverId, this.path);
  final String serverId;
  final String path;
}

/// The launcher (§2.7) — a pane with no location is never blank.
class LauncherLocation extends PaneLocation { const LauncherLocation(); }
```

Local and remote are fully symmetric: both are `RemoteFileSystem`
implementations (D3, `LocalFileSystem` in `poltergeist_core`; interface at
`/home/user/Seance/packages/seance_core/lib/src/ssh/remote_file_system.dart`),
so every pane behavior below is written once against `RemoteFileEntry`.

### 2.1 Path bar

- One segment per path component; **every segment is clickable** and
  navigates to that ancestor (Transmit's model). Segments middle-truncate
  with the ported `MiddleEllipsisText` when cramped; overflowed leading
  segments collapse into a `…` segment whose menu lists them.
- The **rightmost segment opens an ancestor popup** on click-and-hold or on
  its chevron: a menu of all enclosing folders up to the root (and, for
  remote, the server home).
- Left end: a location glyph — the favorite's `ServerIcon` badge for remote
  tabs (with connection state), a folder/volume glyph for local. Clicking it
  opens the connection panel (remote: server info, disconnect, open in
  Séance — v1.x, shown only when the OS reports a `seance://` handler,
  hidden otherwise (04 §7.1); local: volume info).
- Right end: the view-options button (§2.4) and, during navigation, the
  cancel affordance (§2.8).
- `go.editPath` (⌘L / Ctrl+L) swaps the bar for an editable text field
  (prefilled, selected); Enter navigates, Esc restores. `go.toFolder`
  (⇧⌘G / Ctrl+Shift+G) opens the same field as a dialog with history.
- **Focused-pane indicator**: the focused pane's path segments render in the
  accent color; the unfocused pane's in `onSurfaceVariant`. This is
  Transmit's blue-path idea — in a two-pane app the focused side decides
  transfer direction, so the cue must be always-visible. Reinforcements:
  selection highlight in the unfocused pane drops to a neutral tone, and
  explicit focus shortcuts exist (`pane.focusLeft`/`pane.focusRight`,
  ⌥⌘←/⌥⌘→, plus Tab swap — §8).

### 2.2 View modes

Two modes in v1, per pane-tab: **List** (⌘1) — name column only, densest —
and **Details** (⌘2) — multi-column. Both are virtualized: List via
`ListView.builder` with fixed `itemExtent`; Details via
`two_dimensional_scrollables` `TableView.builder` with a pinned header row.
Row extents are fixed per density (§11): 28 px comfortable, 22 px compact.
No thumbnails/columns/cover-flow modes in v1 (research: even Transmit's
Cover Flow is dead weight).

### 2.3 Columns and sorting

Details columns: **Name** (fixed, always first), **Size**, **Date
Modified** on by default; **Kind**, **Permissions**, **Owner**, **Group**
optional (right-click the header to toggle; drag to reorder; widths
persisted). Sorting rules — the comparator lives in `poltergeist_core` and
is unit-tested:

- **Directories first** (default on, a view option; symlinks whose target is
  a directory count as directories).
- **Natural name sort**: case-insensitive (Unicode simple case fold), digit
  runs compared numerically (`file9` < `file10`), case-sensitive tiebreak.
  Deterministic and locale-independent so listings match across platforms.
- First click on Name/Kind sorts ascending; on Size/Date **descending**
  (Finder muscle memory: biggest/newest first). Second click reverses.
  Secondary key is always name ascending. Sort state shows as a chevron in
  the header and is announced to screen readers (§13).
- Sorting sorts the **model**, not the view; the virtualized view only
  materializes visible cells, so re-sort of 100k entries stays in budget.
- Directory sizes display `—`; `view.calculateFolderSizes` computes them on
  demand with progress (never automatically — remote recursion is a cost the
  user opts into).
- Dates render relative for today/yesterday (`Today at 14:32`), absolute
  otherwise; setting `Always show absolute dates`. Size formatting follows
  the platform's file manager: decimal units on macOS/Linux, binary on
  Windows.

### 2.4 View options and per-location persistence

The view-options button (no default shortcut; also in the View menu) opens
a popover: view mode, density, directories-first, hidden files, columns,
relative dates. Options apply to the current location and are persisted
**per location** (key: volume-or-serverId + path, bounded LRU of 500
entries) on top of a **global default**, with a "Use as defaults for all
folders" action — ForkLift is criticized for lacking the global override;
we ship both layers from day one.

### 2.5 Selection, type-ahead, Quick Select, filtering

- Selection follows platform file-manager gestures: click, ⌘/Ctrl-click
  toggle, ⇧-click range, ⌘A/Ctrl+A select all, ⇧⌘I/Ctrl+Shift+I invert.
  Arrow keys move the cursor row; ⇧+arrows extend; Home/End/PageUp/PageDown
  work from day one (ForkLift 4 shipped keyboard-poor and paid for years).
- Right-click selects the row under the cursor first (unless it is already
  in the selection), then opens the context menu.
- **Type-ahead**: printable keys accumulate into a buffer (1 s reset);
  case- and diacritic-insensitive **prefix** match jumps selection to the
  first match and scrolls it visible. ~100 lines over the pane focus node;
  never active while any text field has focus.
- **Quick Select** (`selection.quickSelect`, ⌘E/Ctrl+E — ForkLift's idea): a
  small field drops below the path bar with an Add/Remove segmented toggle.
  Typing matches a name fragment or `*.ext` glob against the listing and
  adds to / removes from the current selection live. Enter confirms and
  closes; Esc reverts to the prior selection.
- **Filter** (`view.filter`, ⌘F/Ctrl+F): filters the visible listing in
  place (substring, case-insensitive), helper text `12 of 348`; Esc clears.
  Per-tab and transient — never persisted (a forgotten filter reads as data
  loss). Filtered-to-nothing shows the dedicated empty state (§2.7).
- **Hidden files**: global setting plus a per-tab override
  (`view.toggleHidden`, ⇧⌘./Ctrl+H) that lasts for the tab's lifetime.
  Remote hidden = dotfiles; local also honors platform hidden attributes.

### 2.6 Row interactions

- **Open**: double-click, or ⌘↓/⌘O on macOS, Enter on Windows/Linux.
  Folders navigate. Files follow the `Double-click action` setting
  (Transmit's default-behavior-as-preference): Open (default) / Edit in
  Poltergeist / Transfer to other pane / Do nothing. "Open" on a local file
  uses the OS default app; on a remote file it runs the managed checkout
  pipeline and then opens (06).
- **Rename**: Return (macOS) / F2 (Windows/Linux) or context menu. Inline
  `TextField` over the row, basename preselected without extension; Esc
  cancels; validation inline (empty, `/`, platform-invalid characters on
  local). Finder's click-and-wait rename is deliberately omitted — on a
  latency-prone remote listing it causes accidental renames.
- **Delete**: ⌘⌫ / Delete. Local → OS trash (D15). Remote → confirm-then-
  permanent by default with the per-server `.poltergeist-trash/` opt-in
  (D15); dialog copy in §10. ⌥⌘⌫ / Shift+Delete deletes permanently with
  its own confirmation.
- **Quick Look / preview**: Space. macOS: `QLPreviewPanel` channel; Windows
  and Linux: the in-app preview panel (D17; text/images/PDF). Remote files
  download to the managed cache first, with visible progress and Esc-cancel.
- **Get Info** (⌘I / Alt+Enter): a non-modal info panel sliding over the
  focused pane's right edge (Transmit's inspector, not a dialog): name,
  kind, size (folders compute on demand), dates, permissions editor per D28
  (octal field + rwx checkboxes, "Apply to enclosed items…" with
  progress/cancel), owner/group (read-only until the D3 `setOwner` upstream
  addition is in the pinned Séance tag, then editable), full path with copy.
  Esc closes; the panel retargets as selection changes.
- Clipboard verbs are real: Copy/Paste files across panes and from/to the
  OS clipboard where the platform allows; `Move Here` (⌥⌘V) / Cut (Ctrl+X)
  per platform convention (§8).

### 2.7 Empty states — never blank

- **Launcher** (`LauncherLocation` — a disconnected/new pane): the pane
  fills with a three-tab launcher, Transmit's "idle pane is a launcher"
  trick: **Servers** (favorite servers with groups and a filter field —
  reusing Séance's `server_grouping.dart`/`server_filter.dart` pure-logic
  patterns, including "filter overrides collapsed groups" and
  `3 of 12 · ↵ opens the first`), **Recent** (auto-tracked recent locations
  and connections, newest first), **Quick Connect** (address field parsing
  `user@host:port` and `sftp://` URLs, connect button, and — after a
  successful connect — a "Save as favorite…" bar prefilled from the live
  connection: capture context instead of forms).
- **Empty folder**: centered `This folder is empty` plus the drop hint
  `Drop files here to copy them` (`…to upload them` for remote).
- **Filtered to nothing**: `No items match "q"` with a Clear button.
- **Connection lost**: the listing dims under a banner
  `Connection to <server> lost — reconnecting…` with Cancel; entries stay
  visible (they are cached data, §2.8) but actions disable.

### 2.8 Latency honesty rules

Remote browsing must feel asynchronous, never frozen (the Nimble
Commander/Mountain Duck anti-patterns). Binding rules:

- **Stale-listing generations**: every navigation increments a per-tab
  generation; listing results carry the generation they answered and are
  dropped if a newer one exists. The Séance `identical()`-recheck idiom plus
  `RemoteTransferCancellation` for the in-flight call.

```dart
class ListingState {
  final PaneLocation location;
  final int generation;          // bumped per navigation
  final List<RemoteFileEntry> entries; // sorted model; view virtualizes
  final bool loading;            // a newer generation is in flight
  final Object? error;           // shown inline, never modal
}
```

- **The old listing stays visible** (dimmed 60% opacity) while the next one
  loads; a 2 px indeterminate progress line runs under the path bar. No
  spinner or dimming appears before **150 ms** — fast navigations must not
  flash.
- **Every navigation is cancellable**: Esc (pane-scoped) or the ✕ that
  replaces the view-options button while loading. Cancel restores the prior
  location and listing exactly.
- The pane footer swaps its counts for `Loading /var/www — Esc cancels`
  while loading; errors render inline in the pane (message + Retry), never
  as modal dialogs.
- Listing overhead budget: network time + < 50 ms (D12).

### 2.9 Pane footer

Per-pane strip: `N items · M selected` plus free space for local volumes or
`user@host` for remote. Doubles as the loading/error line (§2.8).

## 3. Tabs, pane toggle, Workspaces

- **Tabs per pane** (R3): each pane owns a tab strip. ⌘T opens a new tab;
  setting `New tabs open`: Duplicate current location (default) / Home /
  Launcher. ⌘W closes (guarded: a tab with an active transfer *source or
  destination* keeps transfers running — the queue is above panes — but the
  close confirm quantifies any tab-scoped state; the confirmation lives in
  the state operation itself, not the call site — Séance SEA-009 lesson).
  ⇧⌘T reopens the last closed tab (a "ghost tab" ring of 10, defusing
  SEA-032's mistake class). Middle-click closes. ⌃⇥/⌃⇧⇥ (and ⇧⌘]/⇧⌘[)
  cycle within the focused pane.
- Tab titles: `Folder name` (default) / `Server name` / `Server · folder`
  (setting, per Transmit); tooltip shows the full path and server. Remote
  tabs show the favorite's `ServerIcon`/`ServerColor` badge (§4) and a
  connection dot.
- **Drag tabs between panes**: a tab dragged to the other pane's strip moves
  it (its SFTP browse channel moves with it — 03). Dragging the last tab
  away leaves the source pane on the launcher, never blank.
- **One/two-pane toggle** (`view.toggleSecondPane`, ⇧⌘D): hiding pane B
  preserves its full tab set and per-tab state; re-showing restores it
  exactly (ForkLift 4.3.x's remembered pane, which reviewers singled out).
  Auto-hide at stage 2 (§1) uses the same mechanism.
- **State restoration**: on launch, restore geometry, panes, tabs, and
  locations. Remote tabs restore showing their path and cached listing with
  a `Reconnect` bar; they reconnect lazily when activated (setting
  `Reconnect restored tabs automatically`, default on).
- **Workspaces**: a saved snapshot of both panes' tab sets, active tabs, and
  per-tab view state. Saved via `workspace.save` ("Save Workspace…"); stored
  as a favorite kind (§4, schema in 04) so it lands in the sidebar and syncs
  with bookmarks. Opening a workspace replaces both panes' tabs and shows a
  toast `Workspace "Client X" opened` with an **Undo** action restoring the
  prior tab sets. Transfers are unaffected (queue is above panes).

## 4. Sidebar

One global sidebar per window, left side — ForkLift semantics per the
decision log; the persisted schema is 04's contract, this section is the
behavior.

**Fixed sections** (collapsible, not hidable):

- **Devices** — local volumes: system, home, mounted/removable drives with
  hot-plug updates; eject affordance where applicable.
- **Connections** — currently open connections from the connection pool,
  with live state (connecting spinner / connected / error) and a context
  menu (Disconnect, Open in other pane, Open in Séance — v1.x, only when
  the `seance://` handler exists, 04 §7.1).

**Favorites** below, in user-defined groups (reorderable, collapsible;
collapse state persisted device-locally — 04 §2.3). A favorite is *anything
openable* — the key ForkLift idea. The model is 04 §2.1's `Bookmark`, not a
second type: four kinds (`localFolder`, `remotePath`, `workspace` with its
inline left/right `BookmarkLocation`s, `savedSync` with its embedded
`SavedSyncSpec`), a label, a `group` string, a `sortKey`,
`ServerColor`/`ServerIcon` (the `seance_protocol` enums — a host tagged in
one app renders identically in the other), and
`PreferredPane { left, right, either }`, where `either` means "open in the
active pane".

Behaviors:

- **Click opens in the active pane**, replacing its active tab's location —
  unless the favorite's `preferredPane` says left/right (ForkLift 4.2's
  per-connection preferred side, generalized). ⌘/Ctrl-click opens a new tab;
  ⌥/Alt-click opens in the *other* pane. Workspace favorites open per §3;
  saved-sync favorites open the sync preview (05).
- **Custom icon + color** per favorite via the `ServerColor`/`ServerIcon`
  name enums and the accent/badge module ported from
  `lib/ui/server_appearance.dart` (memoized seeded accents, §11). Icons
  appear in tabs too.
- **Sidebar editor** (`View > Customize Sidebar…`): checkbox visibility per
  favorite and group, drag to reorder/regroup; right-click any favorite for
  Edit (rename, icon, color, preferred pane) / Hide from Sidebar / Remove.
- **Adding**: `favorite.add` on the current location ("Add to Favorites…",
  menu/palette, no default shortcut), drag a folder row or a tab onto the
  sidebar, or "Save as favorite…" from Quick Connect.
- **Drop target**: dragging files onto a local-folder or server-path
  favorite starts a transfer to that location (§5). Workspace and saved-sync
  favorites reject drops (no-drop cursor).
- **Status dots via `ProbeService`, tri-state**: server-backed favorites
  show one composed indicator — `unknown` (grey — not yet probed or probing
  disabled), `online`, `offline` (the pinned `ProbeStatus` enum; UI labels
  may render them as reachable/unreachable). Probes are TCP connects to
  host:port, 3 s timeout, every 60 s while the app is foreground, paused in
  background (Séance's foreground gating), rate-limited per host, opt-out
  setting `Probe server reachability`. Colors are theme-aware and
  contrast-checked (fix SEA-019); exactly one dot composed into the badge
  corner (fix SEA-021). The Connections section shows pool state, not probe
  state — live truth outranks probes.
- Groups and filtering reuse the Séance pure-logic patterns (§2.7). The
  sidebar shows a filter field only at ≥ 10 favorites or while a query is
  active.

## 5. Transfers and conflicts

### 5.1 Drag & drop (D14)

- **In-app pane↔pane drags** use Flutter `Draggable`/`DragTarget`: drag
  avatar = stacked file icons with a count badge. Valid targets: the other
  pane's listing background (drop into its current directory), any folder
  row (highlighted; spring-loads open after 1 s hover), sidebar favorites
  (§4), and tab headers (hover 700 ms switches to that tab, then drop
  normally).
- **OS drop-in** via `desktop_drop`, one `DropTarget` per pane, gated on
  `TickerMode` and route-current (the Séance `files_pane.dart:213` wiring)
  so background tabs never swallow drops. The drop position decides hovered
  folder row vs current directory. A drop-hover overlay names the action:
  `Copy to /var/www` / `Upload to /var/www`.
- **Default verb**: within one filesystem (same volume, or same server) a
  drag **moves**; across filesystems/servers it **copies** — matching
  Finder/Explorer. Modifiers force: ⌥ (macOS) / Ctrl (Windows/Linux) =
  copy; ⌘ (macOS) / Shift (Windows/Linux) = move. The avatar badge shows
  the effective verb (`+` for copy).
- Remote→remote drags between two server tabs create a piping task through
  the local machine (D16); the task row names both endpoints.
- **OS drag-out is v1.x** (D14). The transfer queue exposes the
  produce-on-demand hook from day one; until then the context menu carries
  `Download to…`.
- Every drop lands in the **transfer queue** — nothing uploads inline.
  Drop-to-transfer-start < 500 ms with **no upfront full-tree stat**
  (Transmit's instant-start trick; totals grow during the transfer, §5.3).

### 5.2 Conflicts — the 5-verb model

On a name collision the queue pauses that item and asks (unless a default
policy answers). Verbs, exactly (D16, from Transmit):

- **Replace** — overwrite the destination.
- **Replace if newer** — overwrite only when the source mtime is newer;
  otherwise skip. (Shown for folders too, applied per file.)
- **Keep both** — auto-numbered copy: `report (2).pdf`.
- **Skip** — leave the destination; continue the task.
- **Merge** — folders only: recurse, resolving per-file conflicts by the
  file policy.

Plus a **Stop** button that cancels the remaining task. The dialog shows
both versions side by side — name, size, mtime, host — e.g.:

> `report.pdf` already exists in `/var/www` on `prod-web-01`.
> Existing: 8.1 KB, modified yesterday 17:40 · Replacing it with:
> 12.3 KB, modified 2 minutes ago.

An `Apply to all N remaining conflicts in this task` checkbox scopes the
choice to the task. **Per-direction, per-kind configurable defaults**
(Transmit's matrix) live in Settings > Transfers:

```dart
enum ConflictResolution { ask, replace, replaceIfNewer, keepBoth, skip, merge }

class ConflictPolicy {
  final ConflictResolution uploadFiles;    // default: ask
  final ConflictResolution uploadFolders;  // default: ask
  final ConflictResolution downloadFiles;  // default: ask
  final ConflictResolution downloadFolders;// default: ask
}
```

"Resume" is deliberately absent — resumable transfers are v2 (D25); when
ranged read/write ships, Resume joins the dialog for interrupted items.

This settings-level model is canonical; 03 §4.1 defines the resolved
per-task form (`ResolvedConflictPolicy`) that the engine receives at
enqueue time.

### 5.3 Progress rules

- Transfers start instantly; folder tasks show growing totals with an open
  count while enumeration runs: `12 of 34+ files · 108 MB of 410+ MB`. The
  `+` disappears when the scan completes.
- Per-item progress is byte-accurate. Speed is a smoothed rolling average
  (5 s window); ETA appears only after the rate stabilizes (≥ 3 s of data)
  and never jumps more than once per second.
- Failures never modal-interrupt a running queue: the item enters `failed`
  with the error attached (§6); a toast summarizes only when the whole task
  ends with failures.

## 6. Activity panel (D16)

The optional bottom panel — R7 — rendered from the `TransferQueue` service
(03). It is a trust organ: every long operation is visible, cancellable,
inspectable; per-item rows, never just a summary bar (Transmit's launch
mistake).

Two tabs in the panel header: **Activity** and **History**; right side of
the header: queue Pause/Resume toggle, bandwidth button, Clear-completed.

**Activity rows** — one row per task (a task = one user gesture, e.g. one
drop of 200 files):

- Anatomy: direction/kind icon · title (`report.pdf` or
  `214 items to /var/www`) · `source → destination` line (hosts shown with
  their accent badges) · progress bar · `bytes / total · speed · ETA` ·
  actions.
- States: `queued`, `running`, `paused` (queue paused), `failed` (error text
  inline + Retry), `completed` (auto-remove on success — setting, default
  on, 10 s linger), `cancelled`.
- Multi-file tasks expand (chevron) to per-file sub-rows with per-file
  status and a per-file Skip while queued.
- **Reorder** queued tasks by drag; running tasks pin to the top.
- Per-task actions: Cancel, Retry (failed; retries only the failed items),
  Remove, Reveal in pane, Copy error.
- **Queue pause** stops new items from starting; in-flight items finish
  (Transmit's documented semantics — stated in the tooltip:
  `Pause stops new transfers; current files finish`).

**History** — the persistent log (works across restarts; FileZilla's broken
history is the anti-model): time, verb, `source → destination`, result,
error if any; filter field; copyable text; `Clear History`. Backed by the
queue journal (03); capped at 10 000 entries, oldest pruned.

**Bandwidth control**: the header button shows `∞` or the active limit
(`1.5 MB/s`). Its popover has independent Down and Up limits: Off / 256
KB/s / 1 MB/s / 5 MB/s / custom field; token bucket in the engine, applied
immediately, persisted. While limiting, the status bar shows the limit chip.

**Persistent queue**: closing the window with active transfers is
intercepted (`window_manager` prevent-close) — dialog per §10. On next
launch a restored queue arrives **paused** with a persistent banner:
`3 transfers from your last session are paused — Resume · Discard`.

## 7. Sync Browsing

`view.toggleSyncBrowsing` (⌥⌘B / Ctrl+Alt+B) links the two panes'
navigation (ForkLift's Sync Browsing, Transmit's Linked Folder Navigation).

- Enabling records both panes' current directories as the **anchor pair**.
  Afterwards, relative navigation in either pane (into a child, up to a
  parent, path-bar jumps within the anchored subtree) replays in the other
  pane at the same relative path.
- **Graceful suspension** (Transmit's behavior, specified): if the mirrored
  directory does not exist, the other pane stays put and the feature
  *suspends* — both path bars show an amber link-broken chip
  (`Sync browsing suspended — "foo" missing on right`). It auto-resumes as
  soon as a navigation lands on a relative path that exists on both sides.
  Suspension never creates directories and never errors modally.
- While active, both path bars show a link chip; the status bar shows the
  sync-browse chip. Disabling (same shortcut, or either tab
  closing/changing server) drops the link silently.
- Sync Browsing is per pane-pair (window-level), not per tab; switching the
  active tab in either pane suspends until the visible pair matches again.

## 8. Keyboard and command system (D21)

### 8.1 Command registry

Every user action is a registered command; menus (§9), context menus,
shortcuts, the palette, and toolbar buttons are all *renderings* of the
registry. Keyboard completeness is a tested invariant (08 hosts the test:
every registered command is reachable via menu or shortcut or palette).

```dart
enum CommandScope { app, pane, selection, editor }

class AppCommand {
  final String id;                    // 'selection.transferToOtherPane'
  final String Function(AppLocalizations) label;
  final CommandScope scope;
  final List<ShortcutActivator> Function(TargetPlatform) activators;
  final bool Function(CommandContext) enabled;   // drives menu greying too
  final Future<void> Function(CommandContext) run;
}
```

`CommandContext` resolves the focused pane, selection, and active tab at
invocation time — commands never capture stale state. Command ids are
dotted lowerCamel, grouped by noun: `app.*`, `tab.*`, `pane.*`, `go.*`,
`view.*`, `file.*`, `edit.*`, `connect.*`, `selection.*`, `favorite.*`,
`workspace.*`, `queue.*`, `sync.*`.

### 8.2 Focus rules

- One `FocusScope` per pane; the active pane = the scope owning primary
  focus. Tab swaps pane focus when a listing has focus.
- **Single-key shortcuts (Space, Return, F2, Delete, Esc, type-ahead) are
  scoped to the pane focus node** via `Focus.onKeyEvent` — they must never
  fire while a rename field, filter field, path editor, or the editor has
  focus. This is the Flutter-desktop pitfall #4 and Séance's
  `terminalFocused` lesson in another costume; the focus flag pushed to
  native menus is cleared on dispose (fix SEA-008).
- Esc is layered: closes palette/popover > cancels rename/filter/Quick
  Select > cancels navigation (§2.8) > deselects.

### 8.4 Quick Open palette

⇧⌘P / Ctrl+Shift+P opens a centered palette over the window (max width
560): one fuzzy-search field over three ranked sections — **Commands**
(enabled ones first, disabled shown greyed with reason tooltip),
**Favorites** (all kinds, with their icon+color badges), **Recent
locations**. Rules, adopting ForkLift's shortcut-teaching loop:

- Every row shows its shortcut, right-aligned; command rows show their menu
  path (`Go ▸ Go to Folder…`) as a secondary line.
- **Pressing a command's bound shortcut while the palette is open executes
  it** — the palette teaches and accepts the fast path.
- Enter runs the selected row (favorites open per §4 rules); ⌘⏎/Ctrl+Enter
  opens a favorite in the *other* pane; Esc closes.
- Fuzzy match: subsequence with word-boundary bonus; favorites match on
  label, host, and path.

## 10. Dialogs and notices

**Top toasts** — port Séance's `top_toast.dart` verbatim (stacking,
root-overlay resolution, reversed dismiss animation, timer ownership).
Top-anchored stands here too: the bottom edge belongs to the activity panel
and status bar. Rules:

- Toasts carry only **transient outcomes**: `Saved and uploaded.`,
  `Workspace "X" opened` (+ Undo), `Copied path`. Default 4 s; action
  toasts 12 s.
- Anything durable goes to a **persistent banner** (Séance's
  `_UpdateBanner` pattern; SEA-039 is the anti-pattern): update available,
  restored-paused queue (§6), sync-account attention needed, OS keyring
  locked (with Retry). Banners render above the panes, are dismissible, and
  persist across navigation until resolved or dismissed.
- Transfer failures live in the activity panel rows (§5.3); a toast may
  summarize, but the panel is the record. Hidden or dishonest transfer
  state is the category's cardinal sin (D16).

**Destructive dialogs quantify what is lost** (Séance's delete-confirmation
pattern — its server delete counts unsaved managed edits):

- Buttons carry verbs, never "OK": `Delete 12 Items`, `Cancel Transfers and
  Quit`. The safe action is the default button. One dialog at a time —
  modals never stack.
- Remote delete (default confirm-then-permanent, D15):
  `Delete 3 items from prod-web-01? This cannot be undone.` — with names
  listed when ≤ 3, a count and total size otherwise, and the per-server
  option surfaced as a checkbox when enabled: `Move to .poltergeist-trash/
  instead`.
- Permanent local delete: `Permanently delete "report.pdf"? It will skip
  the Trash.`
- Quit with active transfers: `2 transfers are running (1.2 GB remaining).`
  → `Pause and Quit` (default) / `Cancel Transfers and Quit` / `Keep
  Transferring` (cancels the close).
- Editor discard/conflict dialogs are 06's, unchanged from Séance.
- Confirmation logic lives inside the state operation, not at one call
  site (SEA-009 lesson), so every entry point — menu, shortcut, drag —
  gets the same guard.

**Settings** is one screen with five tabs — General / Transfers / Editing /
Sync / Advanced — and this list is the single owner of the settings
surface: every preference this plan names lives in one of these tabs
(03 §6's `SettingsStore` inventory assigns each a storage home), with 06 §8
owning the Editing tab's detail.

## 11. Design language — "quiet chrome" (D11)

The chrome recedes; content (file names, paths, progress) is the interface.
Flutter with a bespoke desktop-density system seeded from Séance's theme
approach — never stock Material-mobile.

- **Theme**: `ColorScheme.fromSeed` per brightness, `useMaterial3`,
  `ThemeMode.system` default with a setting. Poltergeist's seed is its own:
  a muted spectral teal, `0xFF3D8A78` — deliberately distinct from Séance's
  violet so the sibling apps read as family, not clones.
- **Accents**: the `server_appearance.dart` module ported whole — accents
  are `ColorScheme.fromSeed(seed, brightness)` triples, **memoized** on
  `(color, brightness)`; badges compose icon + one status dot ringed in
  surface color; `PositionedDirectional` for RTL. The `ServerColor`/
  `ServerIcon` enums come from `seance_protocol` unchanged (sync-wire
  compatibility, D4).
- **Density**: `VisualDensity.compact` baseline; fixed row extents 28 px
  (comfortable, default) / 22 px (compact, a setting). Controls sized for
  pointer-first use; nothing mobile-padded.
- **Typography**: UI text uses the platform default sans stack. Paths,
  file sizes, permissions, the path-bar editor, and the editor use the
  mono stack from Séance's `theme.dart`: `JetBrains Mono, SF Mono, Menlo,
  Consolas, DejaVu Sans Mono, monospace` (a bare `monospace` family does
  not resolve on Apple platforms). Size and date columns use tabular
  figures so rows align.
- **Iconography**: one outlined icon set (Material Symbols) at 18–20 px,
  single visual weight. File-type icons: the pure-Dart extension→icon map
  as the base layer everywhere; native icons/thumbnails are a later
  per-platform channel behind a seam (03). Remote listings always use the
  base layer.
- **Truncation**: all name/path truncation routes through
  `MiddleEllipsisText` (grapheme-safe, semantics-labeled) — memoized in
  virtualized rows; never ad-hoc `substring` (SEA-006 class).
- **Status colors** are theme-aware and contrast-checked from day one
  (D20; fixes the SEA-019 class rather than porting it).

**Per-platform chrome** — non-negotiable conventions (D11):

| Surface | macOS | Windows | Linux |
|---|---|---|---|
| Titlebar | unified-toolbar look via `macos_window_utils` (`TitlebarSafeArea`) | native titlebar (v1) | server-side decorations |
| Menu bar | native, `PlatformMenuBar` (§9) | Flutter `MenuBar` under titlebar | Flutter `MenuBar` |
| Primary modifier | ⌘ | Ctrl | Ctrl |
| Rename / Open keys | ⏎ / ⌘↓ | F2 / Enter | F2 / Enter |
| Trash verb | Move to Trash | Move to Recycle Bin | Move to Trash |
| Preview | Quick Look panel | in-app preview panel | in-app preview panel |
| File dialogs | native panels (channels) | native (IFileDialog) | GTK native/portal |
| Scroll physics | platform momentum | desktop discrete | desktop discrete |
| Size units | decimal | binary | decimal |

## 13. Accessibility and i18n (D20)

Semantics are hand-built for every custom row type; retrofit is expensive,
so these ship with the widgets:

- **File row**: one merged semantics node — `"report.pdf, PDF document,
  12.3 kilobytes, modified today 14:32"` + selected state; actions for
  open/rename exposed. Column data is announced in Name-Size-Date order
  regardless of visual column order.
- **Column header**: button semantics + sort state (`"Size, sorted
  descending"`).
- **Path segment**: button, `"Go to var"`; the collapsed `…` segment lists
  its menu.
- **Tab**: tab semantics with selected state and a close action.
- **Sidebar group header**: `MergeSemantics` + `Semantics(expanded:)`
  inside the merge, count spelled out — the Séance `server_list_pane.dart`
  standard, kept.
- **Activity row**: label + state; completion and failure announced via a
  live region; progress percent is *not* announced continuously (throttled
  to state changes).
- **Splitters**: focusable, keyboard-resizable (§1), labeled
  (`"Resize sidebar"`) with value announcements.
- **Focus-visible**: a 2 px accent outline on every focusable element,
  never suppressed.
- **Contrast**: text ≥ 4.5:1, indicators and status colors ≥ 3:1 against
  their actual surfaces in both themes; checked by the 08 a11y test over
  the token set.
- **Linux honesty**: Flutter's Linux screen-reader support is broken
  upstream; documented plainly in README/docs, not papered over.

i18n:

- All user-facing strings in ARB via `gen-l10n` from the first widget;
  English-only at v1 but fully externalized; plurals/dates/numbers via
  `intl`. A lint/test (08) fails on hardcoded literals in `lib/ui`.
- **RTL**: layout mirrors under RTL locales (`Directionality`-aware
  spacing, `PositionedDirectional` — already the ported modules' habit).
  Pane commands `focusLeft`/`focusRight` refer to *visual* sides. Paths
  and filenames render inside Unicode directional isolates (LRI/PDI) so
  BiDi filenames cannot reorder path separators.
- **Non-UTF-8 filenames**: SFTP names are byte strings; local Linux names
  can be non-UTF-8 too. v1 policy: decode as UTF-8 strictly; on failure
  the entry is flagged and displayed with U+FFFD replacement characters
  plus a warning badge and a tooltip (`Name is not valid UTF-8; shown
  approximately`), and **rename, delete, and transfer of such entries are
  blocked with an explanatory error** — a lossy display string must never
  round-trip to the wire. Sorting and filtering use the decoded form.
  Byte-preserving operations on non-UTF-8 names are parked (D25).
