# 02 — UX specification

This chapter is the screen-by-screen contract for `app/poltergeist_app`. It
elaborates the decision log in [00-OVERVIEW.md](00-OVERVIEW.md) — especially
D11 (quiet chrome), D12 (performance budgets), D13 (single window), D14
(drag & drop), D16 (activity panel), D17 (editor seams), D20 (a11y/i18n),
D21 (command registry) — and never reopens it. Architecture wiring is 03;
bookmark schema is 04; sync preview UX is 05; editor screens are 06.

Two research sources drive the shapes below: Transmit 5 and ForkLift 4
feature studies, and the Séance UI deep-read (reusable modules and the
SEA-/SOL- debt list of what *not* to copy). Séance file paths cited here are
relative to `/home/user/Seance/app/seance_app` unless prefixed.

## 1. Window anatomy

One window (D13), owned by a `WorkspaceController`. Layout:

```
+---------------------------------------------------------------------------+
| titlebar / toolbar               (per-platform chrome, §11)               |
+-----------+------------------------------+--------------------------------+
| sidebar   | pane A                       | pane B                         |
| Devices   | [tab][tab][+]                | [tab][tab][+]                  |
| Connect-  | [path bar............][view] | [path bar...........][view]    |
|  ions     | [listing                   ] | [listing                    ]  |
| Favorites | [                          ] | [                           ]  |
|  (groups) | [                          ] | [                           ]  |
|           | [pane footer: counts, free ] | [pane footer                ]  |
+-----------+------------------------------+--------------------------------+
| activity panel (optional, D16): task rows | History tab | throttle        |
+---------------------------------------------------------------------------+
| status bar: selection summary · sync-browse chip · transfer chip · limit  |
+---------------------------------------------------------------------------+
```

Regions and their collapse behavior:

| Region | Collapsible | How |
|---|---|---|
| Sidebar | yes | `view.toggleSidebar`; at stage 1 (content width below the 1080 px stage-0 threshold) it auto-collapses to an overlay drawer |
| Pane B | yes | `view.toggleSecondPane` (⇧⌘D); hidden pane state is remembered (§3) |
| Activity panel | yes | `view.toggleActivityPanel`; collapsed state = status-bar transfer chip only |
| Status bar | no | always visible; it is the honesty strip |

Three draggable splitters: sidebar↔panes, pane A↔pane B, panes↔activity
panel. All three reuse Séance's `AdaptivePaneLayout` pattern
(`lib/ui/adaptive_shell.dart`): pure allocation math in a Flutter-free
function, keyed handles, drag-start adoption of rendered widths. Handles are
focusable and keyboard-resizable (arrow keys, 16 px steps) — fixing Séance's
SOL-060/SOL-064 instead of copying them.

**Staged responsive collapse — never a single cliff** (Séance's SEA-015
lesson). Stages, evaluated on window content width:

| Stage | Width | Behavior |
|---|---|---|
| 0 | ≥ 1080 px | sidebar + both panes + optional activity panel |
| 1 | 680–1079 px | sidebar auto-collapses to an overlay drawer (toolbar button + shortcut still open it); both panes remain |
| 2 | < 680 px | pane B auto-hides — a transient auto-hide, not a user hide: it restores on regrow per the rules below, and only an explicit `view.toggleSecondPane` hide persists (§3); single pane + drawer sidebar. Unreachable on desktop by design — the 720 px minimum is enforced against the **content area** (the window minimum is 720 px plus whatever frame chrome the platform adds — stages are evaluated on content width, so a window-frame minimum alone would leave the guarantee at the mercy of per-platform decoration widths), flooring content width above 680; this stage exists for the mobile posture (D29) and is tested at mobile widths, not by shrinking a desktop window |

Rules: exactly one region changes per threshold; auto-collapsed regions
restore automatically on regrow, but a region the *user* hid stays hidden
(user intent outranks responsive logic). Stage 2 doubles as the mobile
posture required by D29.

**Persistence** (fixing SEA-018/SOL-062): persist sidebar width, pane A:B
split **as a ratio**, activity-panel height, activity-panel and sidebar
visibility (explicit `view.toggle*` intent only — the stage-1/stage-2
responsive auto-collapse/auto-hide is recomputed from the restored window
size and never persisted, so a user who quits at a narrow stage relaunches
with the region restored on regrow per §1's collapse rules), and window
geometry. Restore geometry clamped to the current
work area. Defaults: window 1180×760 centered; content-area minimum
720×480 (the window minimum derives from it — content minimum plus the
platform's frame chrome — matching the stage table, never a bare 720 px
outer frame that platform decoration could shrink below 720 content);
sidebar
240 px (min 200, max 320); pane ratio 0.5; activity panel 200 px
(min 120 px, max 50% of window height).

**Status bar** (left to right): active-pane selection summary
(`128 items, 3 selected — 42.1 MB` — the byte total sums **files only**;
selected folders count toward the item count but never toward the bytes
unless their size was computed via §2.3's opt-in, so the honesty strip
never triggers a surprise remote recursion), sync-browsing chip (§7, only when
enabled), bandwidth-limit chip (§6, only when limiting), transfer summary
chip (`↑ 2.3 MB/s · 3 tasks` with a mini progress ring; click toggles the
activity panel; error badge count when tasks failed). Nothing in the status
bar is the *only* representation of anything — it summarizes panes and the
queue, which own the detail.

## 2. Panes — the browser view

Each pane hosts a tab strip (§3); each tab renders one *location*. Locations
are a sealed type in `poltergeist_core` (03 owns the wiring):

```dart
sealed class PaneLocation { const PaneLocation(); }

// All three implement value equality (==/hashCode over their fields):
// locations are keyed per-location (§2.4) and compared to detect
// location changes — identity equality breaks both. 03 owns the impl.
// Paths are canonicalized before construction (trailing slash removed —
// a root path keeps its separator (`/`, `C:\`) rather than collapsing to
// the empty string — '.'/'..' segments resolved (clamping at root),
// Unicode-normalized to NFC (macOS listings
// arrive NFD), and case-folded where the filesystem is case-insensitive
// (Windows volumes, default APFS/HFS+) — the folded/normalized form feeds
// ==/hashCode and the §2.4 key while display keeps typed case) — raw
// strings never reach ==/hashCode,
// so `/var/www` and `/var/www/` are one location and one §2.4 key,
// and a real location change is never masked by a spelling variant.
class LocalLocation extends PaneLocation {
  const LocalLocation(this.path);
  final String path;
}

class RemoteLocation extends PaneLocation {
  const RemoteLocation(this.serverId, this.path);
  final String serverId;
  final String path;
}

/// The launcher (§2.7) — a pane with no location is never blank.
class LauncherLocation extends PaneLocation { const LauncherLocation(); }
```

Local and remote are fully symmetric: both are `RemoteFileSystem`
implementations (D3, `LocalFileSystem` in `poltergeist_core`; interface at
`/home/user/Seance/packages/seance_core/lib/src/ssh/remote_file_system.dart`),
so every pane behavior below is written once against `RemoteFileEntry`.

### 2.1 Path bar

- One segment per path component; **every segment is clickable** and
  navigates to that ancestor (Transmit's model). Segments middle-truncate
  with the ported `MiddleEllipsisText` when cramped; overflowed leading
  segments collapse into a `…` segment whose menu lists them.
- The **rightmost segment opens an ancestor popup** on click-and-hold or on
  its chevron: a menu of all enclosing folders up to the root (and, for
  remote, the server home).
- Left end: a location glyph — the favorite's `ServerIcon` badge for remote
  tabs (with connection state), a folder/volume glyph for local. Clicking it
  opens the connection panel (remote: server info, disconnect, open in
  Séance — v1.x, shown only when the OS reports a `seance://` handler,
  hidden otherwise (04 §7.1); local: volume info).
- Right end: the view-options button (§2.4) and, during navigation, the
  cancel affordance (§2.8).
- `go.editPath` (⌘L / Ctrl+L) swaps the bar for an editable text field
  (prefilled, selected); Enter navigates, Esc restores. `go.toFolder`
  (⇧⌘G / Ctrl+Shift+G) opens the same field as a dialog with history.
  Input resolves against the current location: bare names and relative
  segments join the current path before §2's canonicalization, a leading
  `~` resolves to the local user's home or the server home on remote, and
  a Windows drive letter (`D:\`) switches volumes.
- **Focused-pane indicator**: the focused pane's path segments render in the
  accent color; the unfocused pane's in `onSurfaceVariant`. This is
  Transmit's blue-path idea — in a two-pane app the focused side decides
  transfer direction, so the cue must be always-visible. Reinforcements:
  selection highlight in the unfocused pane drops to a neutral tone, and
  explicit focus shortcuts exist (`pane.focusLeft`/`pane.focusRight`,
  ⌥⌘←/⌥⌘→; Tab swaps panes only while keyboard focus is inside a pane
  listing — §8.2's scoping — so ordinary Tab focus traversal between
  toolbar, sidebar, listing, and status bar survives for keyboard and
  screen-reader users).

### 2.2 View modes

Two modes in v1, resolved per tab through the §2.4 chain with no
transient tier (⌘1/⌘2 write the per-location value, so two tabs on one
location always agree — the "⌘2 persists a per-folder preference" is a
deliberate product decision, stated not implied): **List** (⌘1) — name
column only, densest —
and **Details** (⌘2) — multi-column. Both are virtualized: List via
`ListView.builder` with fixed `itemExtent`; Details via
`two_dimensional_scrollables` `TableView.builder` with a pinned header row.
Row extents are fixed per density (§11): 28 px comfortable, 22 px compact,
multiplied by the active text scale factor (D20) so scaled text never
clips; the product is constant per build (recomputed when the OS scale
changes), which preserves `itemExtent` virtualization.
No thumbnails/columns/cover-flow modes in v1 (research: even Transmit's
Cover Flow is dead weight).

### 2.3 Columns and sorting

Details columns: **Name** (fixed, always first), **Size**, **Date
Modified** on by default; **Kind**, **Permissions**, **Owner**, **Group**
optional (right-click the header to toggle; drag to reorder; widths
persisted). Sorting rules — the comparator lives in `poltergeist_core` and
is unit-tested:

- **Directories first** (default on, a view option; symlinks whose target
  is a directory count as directories — classified **only from metadata
  the listing already carries**: where the entry exposes no target kind
  (SFTP attrs are lstat-style, describing the link), the symlink sorts
  with files rather than costing a per-link round trip, which would
  blow §2.8's < 50 ms listing budget on link-heavy directories).
- **Natural name sort**: case-insensitive (Unicode simple case fold), digit
  runs compared numerically (`file9` < `file10`), case-sensitive tiebreak.
  Deterministic and locale-independent so listings match across platforms.
- First click on Name/Kind/Permissions/Owner/Group sorts ascending; on
  Size/Date **descending**
  (Finder muscle memory: biggest/newest first). Second click reverses.
  Secondary key is always name ascending. Sort state shows as a chevron in
  the header and is announced to screen readers (§13).
- Sorting sorts the **model**, not the view; the virtualized view only
  materializes visible cells, so re-sort of 100k entries stays in budget.
- Directory sizes display `—`; `view.calculateFolderSizes` computes them on
  demand with progress (never automatically — remote recursion is a cost the
  user opts into). Under Size sort, an unevaluated directory compares as
  size 0 (deterministic; the name-ascending secondary key orders them among
  themselves) — part of the comparator contract 03 unit-tests.
- Dates render relative for today/yesterday (`Today at 14:32`), absolute
  otherwise. Relative-vs-absolute is a view option on the §2.4 chain: the
  global default is the `Always show absolute dates` preference, overridable
  per location via the relative-dates option in the view popover (§2.4).
  Size formatting follows the platform's file manager where one convention
  exists — decimal units on macOS, binary on Windows; Linux has no single
  convention (GNOME Files is decimal, KDE Dolphin configurable), so Linux
  defaults to decimal with an explicit decimal/binary preference in
  Settings > General.

### 2.4 View options and per-location persistence

The view-options button (no default shortcut; also in the View menu) opens
a popover: view mode, density, directories-first, hidden files, columns,
relative dates, and **sort key + direction** — List mode's only sort
affordance, since it renders no header row (in Details, §2.3's
header-click sets the same setting). Options apply to the current location and are persisted
**per location** (key: volume-or-serverId + path, bounded LRU of 500
entries) on top of a **global default**, with a "Use as defaults for all
folders" action plus a "Reset this folder to defaults" action (evicting
the location's entry so it inherits the global default again) — ForkLift
is criticized for lacking the global override;
we ship both layers from day one.

This is the one authoritative persistence model for every option above —
column widths and order (§2.3) included, through the same layers:
**global default → per-location persisted value → transient per-tab
override**, where only hidden files has the third layer (§2.5) and the
override is never persisted. Wherever another section mentions one of
these options, it means this chain.

### 2.5 Selection, type-ahead, Quick Select, filtering

- Selection follows platform file-manager gestures: click, ⌘/Ctrl-click
  toggle, ⇧-click range, ⌘A/Ctrl+A select all, ⇧⌘I/Ctrl+Shift+I invert.
  Arrow keys move the cursor row; ⇧+arrows extend; Home/End/PageUp/PageDown
  work from day one (ForkLift 4 shipped keyboard-poor and paid for years).
- Right-click selects the row under the cursor first (unless it is already
  in the selection), then opens the context menu.
- **Type-ahead**: printable keys accumulate into a buffer (1 s reset; Space
  is excluded — it always triggers Quick Look (§2.6), never the buffer, so
  names containing spaces are matched by their non-space prefix — a
  deliberate deviation from Finder, whose type-select buffer does accept
  spaces; Space-always-previews wins that trade here); case- and
  diacritic-insensitive **prefix** match jumps
  selection to the first match and scrolls it visible. ~100 lines over the
  pane focus node; never active while any text field has focus. The
  accumulated buffer renders as a small transient badge while typing, so
  the 1 s reset and the prefix-so-far are visible rather than silent
  (announced politely to screen readers, §13).
- **Quick Select** (`selection.quickSelect`, ⌘E/Ctrl+E — ForkLift's
  idea; ⌘E is Eject in Finder and "Use Selection for Find" in the
  standard Edit menu, a collision the §8 shortcut audit must clear or
  deliberately accept before v1 — recorded here so QA does not discover
  it): a
  small field drops below the path bar with an Add/Remove segmented toggle.
  Typing matches a name fragment or `*.ext` glob against the listing and
  adds to / removes from the current selection live. Enter confirms and
  closes; Esc reverts to the prior selection.
- **Filter** (`view.filter`, ⌘F/Ctrl+F): filters the visible listing in
  place (substring, case-insensitive), helper text `12 of 348`; Esc
  clears — at its §8.2 slot: the field tier while focused, the
  below-navigation tier once unfocused.
  Per-tab and transient — never persisted (a forgotten filter reads as data
  loss). Filtered-to-nothing shows the dedicated empty state (§2.7).
- **Hidden files**: follows the §2.4 precedence chain — global default →
  per-location persisted value (§2.4) → transient per-tab override
  (`view.toggleHidden`, ⇧⌘./Ctrl+H) that lasts for the tab's lifetime and
  is never persisted — **excluded from §3's workspace snapshots and
  session restoration too**, which re-derive hidden visibility from the
  first two links of the chain (a transient reveal captured into a
  synced workspace would resurface on other machines, contradicting
  "never persisted"). Remote hidden = dotfiles; local also honors
  platform
  hidden attributes.

### 2.6 Row interactions

- **Open**: double-click, or ⌘↓/⌘O on macOS, Enter on Windows/Linux.
  Folders navigate. Files follow the `Double-click action` setting
  (Transmit's default-behavior-as-preference): Open (default) / Edit in
  Poltergeist / Transfer to other pane / Do nothing. "Open" on a local file
  uses the OS default app; on a remote file it runs the managed checkout
  pipeline and then opens (06).
- **Rename**: Return (macOS) / F2 (Windows/Linux) or context menu. Inline
  `TextField` over the row, basename preselected without extension; Esc
  cancels; validation inline (empty, `/`, platform-invalid characters on
  local). Finder's click-and-wait rename is deliberately omitted — on a
  latency-prone remote listing it causes accidental renames.
- **Delete**: ⌘⌫ / Delete. Local → OS trash (D15). Remote → confirm-then-
  permanent by default with the per-server `.poltergeist-trash/` opt-in
  (D15); dialog copy in §10. ⌥⌘⌫ / Shift+Delete deletes permanently with
  its own confirmation.
- **Quick Look / preview**: Space. macOS: `QLPreviewPanel` channel; Windows
  and Linux: the in-app preview panel (D17; text/images/PDF). Remote files
  download to the managed cache first, with visible progress and Esc-cancel.
- **Get Info** (⌘I / Alt+Enter): a non-modal info panel sliding over the
  focused pane's right edge (Transmit's inspector, not a dialog): name,
  kind, size (folders compute on demand), dates, permissions editor per D28
  (octal field + rwx checkboxes, "Apply to enclosed items…" with
  progress/cancel), owner/group (read-only until the D3 `setOwner` upstream
  addition is in the pinned Séance tag, then editable), full path with copy.
  Esc closes (at its slot in the §8.2 Esc order); the panel retargets as
  selection changes.
- Clipboard verbs are real: Copy/Paste files across panes and from/to the
  OS clipboard where the platform allows; `Move Here` (⌥⌘V) / Cut (Ctrl+X)
  per platform convention (§8).

### 2.7 Empty states — never blank

- **Launcher** (`LauncherLocation` — a disconnected/new pane): the pane
  fills with a three-tab launcher, Transmit's "idle pane is a launcher"
  trick: **Servers** (favorite servers with groups and a filter field —
  reusing Séance's `server_grouping.dart`/`server_filter.dart` pure-logic
  patterns, including "filter overrides collapsed groups" and
  `3 of 12 · ↵ opens the first`), **Recent** (auto-tracked recent locations
  and connections, newest first), **Quick Connect** (address field parsing
  `user@host:port` and `sftp://` URLs, connect button, and — after a
  successful connect — a "Save as favorite…" bar prefilled from the live
  connection: capture context instead of forms). Bare-form disambiguation
  against scp syntax: in `user@host:token`, a purely numeric token in
  the range 1–65535 is a
  port; anything else (including `/srv/www` or `22-backup`) is an
  scp-style remote start path on the default port. `sftp://` URLs parse
  port and path positionally and are the unambiguous escape hatch. An
  unbracketed host containing more than one colon (`user@2001:db8::1`) is
  rejected with a visible `wrap the IPv6 address in [ ]` hint — the
  heuristic would otherwise silently connect to host `2001` with start
  path `db8::1`.
  Bracketed IPv6 hosts (`user@[2001:db8::1]:2222/path`) parse the port
  after the closing `]` — the plain heuristic must not split an address
  at its first colon — and a numeric token outside 1–65535 is not a
  port: it parses as a path and the field shows a parse hint. An
  **in-range** numeric token is taken as a port and the field hints
  that too (`2222 → port; use sftp://host/2222 for a folder named
  2222`) — a folder literally named `2222` must misroute with a
  visible interpretation, never silently connect to the home
  directory.
  Passwords never enter through this field: a URL may carry `user:pass@`
  userinfo. Strict RFC 3986 terminates userinfo at the **first** `@` and
  requires a literal `@`/`:` in the password to be percent-encoded, but the
  field parses real-world pasted URLs leniently (WHATWG-style): userinfo is
  delimited by the **last** `@` (so a raw `@` in a password does not split
  the host early), its password is the segment after the first `:` within
  that userinfo, and both are extracted **before** the bracketed-IPv6 and
  port/path colon heuristics run on the host portion, so `user:p@ss@host`
  cannot leak a password fragment
  into the field or the "Save as favorite…" prefill — and the parser
  **strips the password component
  with an inline notice** — it is never connected with, never echoed
  into the field or the "Save as favorite…" prefill, and never
  persisted to Recent or a favorite (bookmarks carry `secretRef`s into
  the vault, 04 §2.2; a pasted URL must not become the one path that
  writes a plaintext password into a synced record). The prefill bar
  derives from the live authenticated session, not the raw input
  string.
- **Empty folder**: centered `This folder is empty` plus the drop hint
  `Drop files here to copy them` (`…to upload them` for remote).
- **Filtered to nothing**: `No items match "q"` with a Clear button.
- **Connection lost**: the listing dims under a banner
  `Connection to <server> lost — reconnecting…` with Cancel; entries stay
  visible (they are cached data, §2.8) but actions disable: connection
  loss sets the §2.8 `error` (rendered as this banner rather than the
  inline form), so `verbsEnabled` is false by the existing rule — but the
  banner is keyed on **connection state**, not on `error == null`:
  transport-level auto-reconnect issues no pane navigation until the
  connection is re-established, so §2.8's "navigation issued (Retry
  included)" error-clear never fires mid-reconnect to dismiss the banner
  and hand the dim layer back to the loading state, and the banner clears
  on the first listing that arrives over the healed connection. This dim
  supersedes — never stacks with — §2.8's loading dim: one dim layer at
  a time, and while the banner shows it owns the layer (a reconnect
  overlapping a load would otherwise compound to near-unreadable
  opacity exactly when reassurance matters).

### 2.8 Latency honesty rules

Remote browsing must feel asynchronous, never frozen (the Nimble
Commander/Mountain Duck anti-patterns). Binding rules:

- **Stale-listing generations**: every navigation increments a per-tab
  generation; listing results carry the generation they answered and are
  dropped if a newer one exists — **error responses too**: an error
  carries its issued generation and is dropped when stale, exactly like
  a successful listing. The Séance `identical()`-recheck idiom plus
  `RemoteTransferCancellation` for the in-flight call.

```dart
class ListingState {
  final PaneLocation location;   // target of the last-issued navigation,
                                 // set optimistically at issue time — the
                                 // location verbs resolve against. Verbs
                                 // stay disabled until a listing for THIS
                                 // location has been accepted — entries can
                                 // still belong to the previous location
                                 // while a navigation is in flight and
                                 // after an error or Esc-cancel — already
                                 // guaranteed by construction (location and
                                 // entries never diverge across the rows
                                 // below), stated here so the invariant
                                 // isn't left to re-derivation
  final int issuedGeneration;    // bumped per navigation; a listing
                                 // response carrying an older generation
                                 // than this is dropped on arrival
  final int answeredGeneration;  // generation of the last ACCEPTED
                                 // answer — listing or error; after an
                                 // error (and after Esc-cancel) `entries`
                                 // are OLDER than this, so entry freshness
                                 // is not derivable from generations alone
  final List<RemoteFileEntry> entries; // sorted, UNMODIFIABLE copy,
                                 // written only by the "listing arrives"
                                 // row and the Esc-cancel snapshot restore
                                 // — no reducer sorts or mutates it in
                                 // place, which would move the model
                                 // without moving a generation and defeat
                                 // stale-detection. Local panes use the
                                 // same type — D3's one-VFS rule
                                 // (LocalFileSystem returns
                                 // RemoteFileEntry), not an oversight.
  // Derived, never stored — a stored copy would desync the moment a
  // reducer sets `error` without recomputing it. A failed or cancelled
  // generation is NOT loading: without the error term, the dim/
  // progress/footer busy states of §2.8 would co-render with the
  // inline error.
  bool get loading =>
      issuedGeneration > answeredGeneration && error == null;
  // Verbs act on `location`; they are live only on a fresh, error-free
  // listing. Freshness can't be read from generations alone — post-error
  // and post-cancel both have answeredGeneration == issuedGeneration with
  // opposite freshness — so it keys on the error term and loading.
  bool get verbsEnabled => error == null && !loading;
  final Object? error;           // shown inline, never modal
}
```

The transitions close over every field — each row is normative, so no
implementation can skip the error-clear step:

| Event | Effect |
|---|---|
| navigation issued (Retry included) | **on the not-loading → loading transition only**, FIRST capture the Esc-cancel snapshot — the prior location, prior unmodifiable entries, and prior displayed error, all read *before* the mutations below overwrite them — then `location = target` (optimistic, so verbs resolve against where we are going); `issuedGeneration++`; `error = null`. The snapshot is never re-captured while a navigation is already outstanding, so a navigation stacked on an unresolved one keeps the last *quiescent* snapshot rather than a transient mid-navigation state — an in-flight retry must read as loading, not as the stale error |
| listing arrives, generation current | `entries` (an unmodifiable sorted copy) + `answeredGeneration = gen`; `error = null` |
| error arrives, generation current | `error` set; `answeredGeneration = gen` (the generation answered — with an error); row verbs over the still-visible stale `entries` **disable** until a listing is accepted — the §2.7 cached-data rule, because operations resolve against the *current* `location` and a name match against another directory's listing would hit the wrong file |
| listing or error arrives, generation stale | dropped entirely |
| Esc-cancel | cancels **every** in-flight generation for the pane and restores the **last quiescent snapshot** (the one captured on the not-loading → loading transition) — prior location, prior entries, **and any `error` that was displayed before the issue cleared it** (a cancelled Retry returns to its inline error and Retry affordance, never to a silently clean pane showing another directory's listing as current); because the snapshot is only ever the last quiescent state, cancelling a navigation stacked on an earlier unresolved one lands on a listing that actually belongs to the shown location, never a transient location=Y/entries=X mix — then `issuedGeneration++` and `answeredGeneration = issuedGeneration` — the counter **never moves backward**: a downward reset would leave a late response from a cancelled navigation carrying a generation *newer* than issued, a case no row covers, and could make `loading` read false during the next real navigation; advancing instead makes every cancelled-navigation response stale, so the drop rule swallows it, and `loading` reads false — cancellation is never modeled by setting `error` |

- **The old listing stays visible** (dimmed 60% opacity) while the next one
  loads; a 2 px indeterminate progress line runs under the path bar. No
  spinner or dimming appears before **150 ms** — fast navigations must not
  flash.
- **Every navigation is cancellable**: Esc (pane-scoped) or the ✕ that
  replaces the view-options button while loading. Cancel cancels **all**
  in-flight generations for the pane and restores the last quiescent
  snapshot — captured only on the not-loading → loading transition, never
  re-captured while a navigation is already outstanding — so cancelling a
  navigation stacked on an earlier unresolved one lands on a listing that
  belongs to the shown location, the transition table's generation
  reconciliation included.
- The pane footer swaps its counts for `Loading /var/www — Esc cancels`
  while loading, behind the same 150 ms anti-flash grace as the dim — so
  a sub-150 ms navigation never flashes counts → Loading → counts (nor a
  briefly-appearing Esc affordance); errors render inline in the pane
  (message + Retry), never as modal dialogs.
- Listing overhead budget: network time + < 50 ms (D12).
- A navigation with no response within the adapter's 30 s operation
  timeout (03 §3.3) routes through the error-arrives row above (generation
  current): inline error + Retry over the stale listing, never a
  perpetual dim/spinner; Esc remains the immediate manual out.

### 2.9 Pane footer

Per-pane strip: `N items · M selected` plus free space for local volumes or
`user@host` for remote. Doubles as the loading/error line (§2.8).

## 3. Tabs, pane toggle, Workspaces

- **Tabs per pane** (R3): each pane owns a tab strip. ⌘T opens a new tab;
  setting `New tabs open`: Duplicate current location (default) / Home /
  Launcher. ⌘W closes (guarded: a tab with an active transfer *source or
  destination* keeps transfers running — the queue is above panes — but the
  close confirm quantifies any tab-scoped state — the trigger set is
  exactly: an in-flight navigation, an in-flight folder-size
  computation, an active inline rename, an in-flight "Apply to enclosed
  items…" permissions operation (§2.6, a recursive chmod/chown over a
  remote tree), and a tab holding a Sync
  Browsing anchor (§7); nothing else fires it, so with none present ⌘W
  closes silently (Quick Look preview-cache downloads are pane-owned and
  Esc-cancellable, so they continue rather than confirm). The confirmation lives in
  the state operation itself, not the call site — Séance SEA-009
  lesson — and middle-click close routes through the same operation, so
  it cannot bypass the guard).
  ⇧⌘T reopens the last closed tab (a "ghost tab" ring of 10, defusing
  SEA-032's mistake class). Middle-click closes. Closing a pane's last
  tab (⌘W or middle-click, guard permitting) leaves that pane on the
  launcher — the same state as dragging the last tab away — never blank
  and never an auto-opened tab. ⌃⇥/⌃⇧⇥ (and ⇧⌘]/⇧⌘[)
  cycle within the focused pane.
- Tab titles: `Folder name` (default) / `Server name` / `Server · folder`
  (setting, per Transmit); tooltip shows the full path and server. Remote
  tabs show the favorite's `ServerIcon`/`ServerColor` badge (§4) and a
  connection dot.
- **Drag tabs between panes**: a tab dragged to the other pane's strip moves
  it (its SFTP browse channel moves with it — 03). Dragging the last tab
  away leaves the source pane on the launcher, never blank.
- **One/two-pane toggle** (`view.toggleSecondPane`, ⇧⌘D): hiding pane B
  preserves its full tab set and per-tab state; re-showing restores it
  exactly (ForkLift 4.3.x's remembered pane, which reviewers singled out).
  Auto-hide at stage 2 (§1) uses the same mechanism.
- **State restoration**: on launch, restore geometry, panes, tabs, and
  locations. Remote tabs restore showing their path and cached listing with
  a `Reconnect` bar. With `Reconnect restored tabs automatically` on
  (default), activating a restored tab reconnects it with no click; with
  it off, the bar stays until the user clicks `Reconnect` — activation
  alone never reconnects (the metered/VPN case the setting exists for).
- **Workspaces**: a saved snapshot of both panes' tab sets, active tabs, and
  per-tab view state. Saved via `workspace.save` ("Save Workspace…"); stored
  as a favorite kind (§4, schema in 04) so it lands in the sidebar and syncs
  with bookmarks. Opening a workspace routes both panes' tab replacement
  through the same tab-scoped-state operation ⌘W uses (same trigger set:
  in-flight navigation, folder-size computation, inline rename, "Apply to
  enclosed items…" operation, Sync anchor) before replacing anything, then
  replaces both panes' tabs and shows a
  toast `Workspace "Client X" opened` with an **Undo** action restoring the
  prior tab sets (which cannot restore in-flight state, hence the guard first). Transfers are unaffected (queue is above panes).

One global sidebar per window, left side — ForkLift semantics per the

**Fixed sections** (collapsible, not hidable):

**Favorites** below, in user-defined groups (reorderable, collapsible;

Behaviors:

- **Click opens in the active pane**, replacing its active tab's location —

  ⌥/Alt-click opens in the pane **opposite the one a plain click would
  use** (the active pane for `either`, the preferred pane for left/right)

  plain clicks only, and unhides the target pane if it was hidden — except
  in the stage-2 mobile posture (§1), where a second pane cannot be shown
  and the modifier-click opens in the visible pane instead.
  Workspace favorites open per §3;
  saved-sync favorites open the sync preview (05).
- **Custom icon + color** per favorite via the `ServerColor`/`ServerIcon`
  name enums and the accent/badge module ported from
  `lib/ui/server_appearance.dart` (memoized seeded accents, §11). Icons

- **Sidebar editor** (`View > Customize Sidebar…`): checkbox visibility per

  contrast-checked (fix SEA-019); exactly one dot composed into the badge

## 5. Transfers and conflicts

### 5.1 Drag & drop (D14)

- **In-app pane↔pane drags** use Flutter `Draggable`/`DragTarget`: drag
  avatar = stacked file icons with a count badge. Valid targets: any pane's
  listing background (drop into its current directory — same-pane drops
  included), any folder row in either pane (highlighted; spring-loads
  open after 1 s hover; same-pane drops follow the same verb rules), sidebar favorites
  (§4), and tab headers (hover 700 ms switches to that tab, then drop
  normally).
- **OS drop-in** via `desktop_drop`, one `DropTarget` per pane, gated on
  `TickerMode` and route-current (the Séance `files_pane.dart:213` wiring)
  so background tabs never swallow drops. The drop position decides hovered
  folder row vs current directory. A drop-hover overlay names the action:
  `Copy to /var/www` / `Upload to /var/www`.
- **Default verb**: within one filesystem (same volume, or same server) a
  drag **moves**; across filesystems/servers it **copies** — matching
  Finder/Explorer. Modifiers force: ⌥ (macOS) / Ctrl (Windows/Linux) =
  copy; ⌘ (macOS) / Shift (Windows/Linux) = move. The avatar badge shows
  the effective verb (`+` for copy). OS drop-in always **copies**: a
  cross-application drag carries no move intent the app can honor
  (deleting from Finder's or Explorer's source on drop is not the
  cross-app convention and the payload does not reliably negotiate it),
  so the same-volume move rule applies to in-app drags only.
- Remote→remote drags between two server tabs create a piping task through
  the local machine **when the tabs are on different servers** (D16); the
  task row names both endpoints. Same-server remote→remote is split by
  verb: a **move** stat-checks the destination first and pauses for the
  §5.2 conflict question on a name collision — the server-side rename
  must carry SFTP v3 `SSH_FXP_RENAME` **fail-on-existing-target**
  semantics, never the `posix-rename@openssh.com` extension, whose silent
  atomic overwrite would return success and bypass §5.2's collision
  prompt entirely (silent data loss) — then executes server-side as a
  rename-class operation (no data through the local machine) for
  whole-entry verbs only — Replace renames the destination aside to a
  temp name first, then renames the source into place, and deletes the
  temp entry only after that rename succeeds; a failed rename restores
  the temp so the destination is never destroyed without its replacement
  landing (orphaned temps from a mid-sequence disconnect are cleaned up
  on reconnect and named so they're identifiable); Skip is a no-op; a
  file Replace-if-newer that evaluates
  to overwrite does the same. **Keep both** on a same-server move is also a
  rename — into the just-stat-verified-free numbered name (`report (2)`),
  fail-on-existing so a race that filled it re-routes through §5.2 rather
  than overwriting — since §5.2 now completes the move by removing the
  source. The recursing verbs (Merge, folder Replace-if-newer applied per
  file) stay non-renames — recursion is not a rename-class primitive — so
  they take the piped path a copy uses, source deletion governed by
  §5.2's per-verb disposition, honoring every conflict answer already
  given — falling back — but only after **re-statting the
  destination** — when the server
  rejects the rename with a **generic failure**
  (`SSH_FX_FAILURE`/`OP_UNSUPPORTED` — SFTP v3 status replies carry no
  errno, so a cross-device EXDEV rejection, the usual cause at mount
  boundaries like `/tmp` → `/var/www` which no SFTP rename can cross,
  is indistinguishable both from other generic failures *and from a
  target that appeared after the pre-move stat-check*, since a v3
  rename onto an existing target is itself a generic failure; the
  re-stat closes that hole — a destination that now exists is a live
  collision routed through §5.2 (asking only when no prior answer
  covers it), never a silent overwrite, and only a still-absent
  destination pipes — and the fallback
  must not wait for a signal the protocol cannot send;
  `NO_SUCH_FILE`/`PERMISSION_DENIED` surface as the real errors they
  are, never a silent copy attempt), to the
  same piped copy-then-delete path a copy uses, without re-asking any
  conflict question already answered and with the task row updated to
  name the actual mechanism; a **copy** still pipes, because SFTP
  v3 has no server-side copy primitive (the `copy-file` extension /
  exec-channel `cp` are D25-class accelerations). Both still enqueue in
  the transfer queue so they stay visible and cancellable (§6).
- **OS drag-out is v1.x** (D14). The transfer queue exposes the
  produce-on-demand hook from day one; until then the context menu carries
  `Download to…`.
- Every drop lands in the **transfer queue** — nothing uploads inline.
  Drop-to-transfer-start < 500 ms with **no upfront full-tree stat**
  (Transmit's instant-start trick; totals grow during the transfer, §5.3).

### 5.2 Conflicts — the 5-verb model

On a name collision the queue pauses that item and asks (unless a default
policy answers). Verbs, exactly (D16, from Transmit):

- **Replace** — overwrite the destination. For a folder collision this is
  **wholesale replacement**: matching entries are overwritten and
  destination-only entries are deleted (mirror semantics; the deletion is
  quantified in the dialog copy). Use **Merge** to recurse without touching
  destination-only entries — that is the only difference between the two
  folder verbs, so it is stated here, not implied.
- **Replace if newer** — overwrite only when the source mtime is newer
  **by more than the same 2 s mtime tolerance D6 defines for the sync
  engine** (the 05 §4 comparison window: SFTP v3 truncates mtimes to
  whole seconds, cross-machine clocks skew, and FAT-class filesystems
  quantize to 2 s,
  so an exact comparison would silently invert under drift — the exact
  hazard 05's engine already absorbs); otherwise skip. (Shown for
  folders too, applied per file.)
- **Keep both** — auto-numbered copy: the first **free** `report (n).pdf`
  (`(2)`, `(3)`, …), generated from the base name with any existing
  trailing `(n)` suffix stripped (a source `report (2).pdf` numbers to
  `report (3).pdf`, never `report (2) (2).pdf`), each candidate stat-checked so a pre-existing
  `report (2).pdf` is itself a name collision resolved through §5.2 —
  never a silent overwrite of the numbered file (on the same-server move
  path name selection and the copy are separated by queue processing,
  which widens exactly the window this closes).
- **Skip** — leave the destination; continue the task.
- **Merge** — folders only: recurse, resolving per-file conflicts by the
  file policy.

Source disposition, for **move** tasks (the default verb for same-volume
pane↔pane and same-server remote→remote drags, §5.1): Skip leaves the
source **untouched** — nothing is deleted, so Skip never destroys user
data. Keep both completes the move: the source is deleted **only after the
numbered copy fully lands** (a failed or partial numbered copy leaves it in
place), so neither kept version is ever destroyed and the move does not
silently degrade to a copy — while Replace and Replace if newer delete the
source **only for the items they actually overwrite**, so a
Replace-if-newer that evaluates to skip leaves its source in place.
**Merge** moves each source item it actually transfers (the per-file
Replace analog) and removes the source folder only once every entry
transferred — any **skipped** item, and the folder while it still holds
one, stays put (a kept-both item is transferred, so it no longer pins the
folder). The transfer engine must never unconditionally
delete sources after conflict resolution (03 §4.1's `ResolvedConflictPolicy`
carries this so the engine cannot).

Plus a **Stop** button that cancels the remaining task. The dialog shows
both versions side by side — name, size, mtime, host (a folder shows its
entry count or a lazily-filled size, never blocking on a recursive stat,
per §5.1's no-upfront-enumeration budget) — e.g.:

> `report.pdf` already exists in `/var/www` on `prod-web-01`.
> Existing: 8.1 KB, modified yesterday 17:40 · Replacing it with:
> 12.3 KB, modified 2 minutes ago.

An `Apply to all N remaining conflicts in this task` checkbox scopes the
choice to the task — the per-file conflicts a **Merge** meets while
recursing included: with the box checked they resolve by the chosen
verb's file analog (Replace → replace, Replace if newer →
replace-if-newer, Keep both → keep-both, Skip → skip, Merge →
keep-merging: nested folder collisions continue to recurse with
destination-only entries preserved, and colliding files
overwrite-the-match — never folder-level replace, whose definition
above deletes destination-only entries, the exact outcome the user
chose Merge to avoid)
and never
re-prompt, so checking the box genuinely lets the user walk away;
unchecked, nested conflicts follow the file policy, which may ask
(03 §4.1's `ResolvedConflictPolicy` mirrors this rule). **Per-direction, per-kind configurable defaults**
(Transmit's matrix) live in Settings > Transfers:

```dart
enum ConflictResolution { ask, replace, replaceIfNewer, keepBoth, skip, merge }

class ConflictPolicy {
  final ConflictResolution uploadFiles;    // default: ask
  final ConflictResolution uploadFolders;  // default: ask
  final ConflictResolution downloadFiles;  // default: ask
  final ConflictResolution downloadFolders;// default: ask
  // Local↔local transfers only — both endpoints local: pane↔pane
  // copies/moves (same or different volume). A remote→local pane↔pane
  // transfer uses the download pair by direction, not these. OS drop-in /
  // cross-app paste onto a local pane lands here (sources outside the
  // panes follow the destination — the §5.2 bucket-mapping paragraph):
  final ConflictResolution localFiles;     // default: ask
  final ConflictResolution localFolders;   // default: ask
  // Remote→remote transfers (§5.1, D16) — cross-server pipes through the
  // local machine, same-server moves execute server-side; one bucket
  // covers both mechanisms:
  final ConflictResolution remoteToRemoteFiles;   // default: ask
  final ConflictResolution remoteToRemoteFolders; // default: ask
}
```

`merge` is valid only in the `*Folders` fields: settings load/save reject
it elsewhere (falling back to `ask`) and the Settings > Transfers matrix
greys it out for file rows — 03 §4.1's `ResolvedConflictPolicy` carries
the same validation.

Every transfer direction that can collide maps to exactly one bucket:
local↔remote picks upload/download by direction, local↔local uses the
`local*` pair, remote→remote (piped or server-side) uses the
`remoteToRemote*` pair. Sources outside the panes follow the
**destination**: OS drop-in (§5.1) and a cross-app clipboard paste
(`edit.paste`/`edit.moveHere` with files copied from Finder/Explorer)
always **copy** — the external source is never deleted, for the same
reason OS drop-in always copies (§5.1: cross-app payloads do not reliably
negotiate move intent), so `edit.moveHere` deletes sources only for
in-app pane↔pane moves — and
onto a local pane use the `local*` pair, onto a remote pane or a
server-path favorite the upload pair; `Download to…` uses the download
pair — no day-one entry point is left to guess its bucket. 03 §4.1's
`ResolvedConflictPolicy` mirrors this dimensionality.

"Resume" is deliberately absent — resumable transfers are v2 (D25); when
ranged read/write ships, Resume joins the dialog for interrupted items.

This settings-level model is canonical; 03 §4.1 defines the resolved
per-task form (`ResolvedConflictPolicy`) that the engine receives at
enqueue time.

### 5.3 Progress rules

- Transfers start instantly; folder tasks show growing totals with an open
  count while enumeration runs: `12 of 34+ files · 108 MB of 410+ MB`. The
  `+` disappears when the scan completes.
- Per-item progress is byte-accurate. Speed is a smoothed rolling average
  (5 s window); ETA appears only after the rate stabilizes (≥ 3 s of data)
  and never jumps more than once per second.
- Failures never modal-interrupt a running queue: the item enters `failed`
  with the error attached (§6); a toast summarizes only when the whole task
  ends with failures.

## 6. Activity panel (D16)

The optional bottom panel — R7 — rendered from the `TransferQueue` service
(03). It is a trust organ: every long operation is visible, cancellable,
inspectable; per-item rows, never just a summary bar (Transmit's launch
mistake).

Two tabs in the panel header: **Activity** and **History**; right side of
the header: queue Pause/Resume toggle, bandwidth button, Clear-completed.

**Activity rows** — one row per task (a task = one user gesture, e.g. one
drop of 200 files):

- Anatomy: direction/kind icon · title (`report.pdf` or
  `214 items to /var/www`) · `source → destination` line (hosts shown with
  their accent badges) · progress bar · `bytes / total · speed · ETA` ·
  actions.
- States: `queued`, `running`, `paused` (queue paused), `failed` (error text
  inline + Retry), `completed` (auto-remove on success — setting, default
  on, 10 s linger), `cancelled`.
- Multi-file tasks expand (chevron) to per-file sub-rows with per-file
  status and a per-file Skip while queued.
- **Reorder** queued tasks by drag; running tasks pin to the top.
- Per-task actions: Cancel, Retry (failed; retries only the failed items),
  Remove, Reveal in pane, Copy error. Reveal in pane falls back to opening
  the task's destination location in the active pane when the originating
  tab no longer exists (tabs may close while transfers run, §3) — the
  action is never a no-op or an error.
- **Queue pause** stops new items from starting; in-flight items finish
  (Transmit's documented semantics — stated in the tooltip:
  `Pause stops new transfers; current files finish`).

**History** — the persistent log (works across restarts; FileZilla's broken
history is the anti-model): time, verb, `source → destination`, result,

**Bandwidth control**: the header button shows `∞` or the active limit

immediately, persisted. While limiting, the status bar shows the limit chip.

**Persistent queue**: closing the window with active transfers is
intercepted (`window_manager` prevent-close) — dialog per §10. On next

## 7. Sync Browsing

`view.toggleSyncBrowsing` (⌥⌘B / Ctrl+Alt+B) links the two panes'
navigation (ForkLift's Sync Browsing, Transmit's Linked Folder Navigation).

- Enabling records both panes' current directories as the **anchor pair**.
  Afterwards, relative navigation in either pane (into a child, up to a
  parent, path-bar jumps within the anchored subtree) replays in the other
  pane at the same relative path. Navigation that would escape the anchor
  root — up past it, or a jump outside the subtree — **suspends** under the
  same mechanism as the missing-directory case below (the navigating pane
  completes its move; the other pane stays put) rather than replaying `..`
  chains; the anchor pair itself never moves while the link is enabled. The
  suspension trigger is explicitly two-case — mirror-does-not-exist **or**
  the target relative path escaping the anchored subtree — with distinct
  chip copy per cause (`"foo" missing on right` vs `outside the anchor
  subtree` — the cause worded as a state, never the bare word "left",
  which reads as the left pane), and
  auto-resume follows the single predicate stated below (both panes at the
  same relative path inside the anchored subtree, existing on both sides).
- **Graceful suspension** (Transmit's behavior, specified): if the mirrored
  directory does not exist, the other pane stays put and the feature
  *suspends* — both path bars show an amber link-broken chip
  (`Sync browsing suspended — "foo" missing on right`). It auto-resumes
  under the single predicate every suspension case shares: the next
  navigation (or re-visibility of the anchored pair, per the tab-switch
  rule below) that leaves **both** panes at the **same** relative path —
  inside the anchored subtree, existing on both sides. Nothing snaps into
  place on resume; a pane only ever moves by its own navigation being
  replayed.
  Suspension never creates directories and never errors modally.
- While active, both path bars show a link chip; the status bar shows the
  sync-browse chip. Disabling via the shortcut, or a tab changing server,
  drops the link silently — a server change explicitly overrides the
  escape-suspension rule above (the anchor pair is meaningless across
  servers) and takes effect only when that navigation commits, so an
  Esc-cancelled server change (§2.8) restores the pane snapshot and keeps
  the link; **closing** an anchored tab instead routes
  through §3's ⌘W guard (which quantifies the anchor loss), so the link
  drops only on a confirmed close, never as a silent side effect of an
  unconfirmed one.
- Sync Browsing is per pane-pair (window-level), not per tab; the anchor
  binds to the two tabs that were visible when it was enabled. Switching
  the active tab in either pane suspends; it resumes only when both
  anchored tabs are the visible pair again **and** their current locations
  sit at a shared relative path (the auto-resume rule above, evaluated at
  wherever the anchored tabs have since navigated). Closing an anchored
  tab drops the link, per the previous bullet. Dragging an anchored tab to
  the other pane (§3) drops it silently too — both anchors must never share
  one pane. Hiding a pane via §3's
  one-pane toggle **suspends** the link exactly as a tab switch does —
  navigation is never replayed into a hidden pane's tab — and
  re-showing the pane resumes only under the same rule: both anchored
  tabs visible again at a shared relative path.

## 8. Keyboard and command system (D21)

### 8.1 Command registry

Every user action is a registered command; menus (§9), context menus,
shortcuts, the palette, and toolbar buttons are all *renderings* of the
registry. Keyboard completeness is a tested invariant (08 hosts the
test: every registered command is reachable via **menu or shortcut** —
palette inclusion is universal by construction and asserted separately,
so it can never by itself satisfy the invariant; counting it would make
the test unfailable and the property vacuous).

```dart
enum CommandScope { app, pane, selection, editor }

class AppCommand {
  final String id;                    // 'selection.transferToOtherPane'
  final String Function(AppLocalizations) label;
  final CommandScope scope;
  final List<ShortcutActivator> Function(TargetPlatform) activators;
  final bool Function(CommandContext) enabled;   // drives menu greying too
  // Renders as the palette's greyed-row reason tooltip (§8.4) and menu
  // tooltips when `enabled` is false. `enabled` defaults to a shared
  // always-true sentinel (`_alwaysEnabled`); the registry constructor
  // asserts `identical(enabled, _alwaysEnabled) || disabledReason != null`
  // — closures can't be inspected for "can return false", so overriding
  // the sentinel is the only enforceable trigger — otherwise §8.4's
  // greyed-row reason has no data source and is silently dropped (08
  // covers the registration-time check).
  final String? Function(AppLocalizations, CommandContext)? disabledReason;
  final Future<void> Function(CommandContext) run;
}
```

`CommandContext` resolves the focused pane, selection, and active tab at
invocation time — commands never capture stale state. Command ids are
dotted lowerCamel, grouped by noun: `app.*`, `tab.*`, `pane.*`, `go.*`,
`view.*`, `file.*`, `edit.*`, `connect.*`, `selection.*`, `favorite.*`,
`workspace.*`, `queue.*`, `sync.*`.

### 8.2 Focus rules

- One `FocusScope` per pane; the active pane = the scope owning primary
  focus. Tab swaps pane focus when a listing has focus — and because
  that consumes the standard traversal key inside listings,
  keyboard-only users leave a listing via **section cycling on
  ⌃F6 / Ctrl+F6** (⇧⌃F6 / Ctrl+Shift+F6 reverse): sidebar ▸ left pane ▸
  right pane ▸ activity panel ▸ the three splitters, documented in the shortcut
  help (plain F6 is taken by `selection.moveToOtherPane` on Windows/Linux
  and left unbound on macOS, §8.3, so the
  Windows F6-cycling convention shifts to the chorded form).
- **Single-key shortcuts (Space, Return/Enter, Tab, Backspace, F2, F5,
  F6, Delete, Esc, type-ahead) are
  scoped to the pane focus node** via `Focus.onKeyEvent` — they must never
  fire while a rename field, filter field, path editor, or the editor has
  focus. The list is every unmodified key the §8.3 table binds **on any
  platform** (the union across platform columns — F2/F5/F6/Backspace/
  Delete bind only on some, so a per-platform lockstep test intersects
  this list with that platform's column) — plus Esc
  and type-ahead, which this section owns rather than the table — kept in
  lockstep with it; treating an earlier shorter list as exhaustive
  would leave Tab/Backspace/F5/F6 firing global while the user types.
  This is the Flutter-desktop pitfall #4 and Séance's
  `terminalFocused` lesson in another costume; the focus flag pushed to
  native menus is cleared on dispose (fix SEA-008). The same field-first
  precedence holds for modified text chords (⌘C/⌘V/⌘X/⌘Z/⌘A and their
  Ctrl-equivalents, plus ⌘F while the editor has focus, 06): wherever a
  text surface holds focus, its own shortcuts win and no registry command
  fires — §8.4's palette carve-out and §9's macOS retargeting are explicit
  instances of this general rule, which governs plain in-window dispatch
  on every platform (08 asserts it).
- **Space always fires Quick Look** (`file.preview`) and never joins the
  type-ahead buffer (§2.5); a pending type-ahead match resolves first,
  then Space previews the row the buffer landed on — one precedence
  rule, so mid-search Space can never mean "search for a literal
  space".
- Esc is layered — this list is the total order (every dismissible
  surface appears in exactly one tier, and one press fires one tier);
  when several apply, the
  highest wins: cancels the showing modal dialog (§10 — a modal owns
  focus and its Esc never reaches the pane tiers; listed here so the
  total order really is total) > closes palette/popover > closes Quick Look / the
  preview panel (`file.preview` — a stuck-open preview with Esc doing
  something else would read as broken; 06 §5.2's Esc-cancels-download
  state is this same tier acting on the in-flight production) > cancels
  rename/filter/Quick
  Select/path editor (field-focused surfaces — the ⌘L path editor
  (`go.editPath`, §8.3) is one of them, so Esc cancels the half-edited
  path rather than falling through to commit it, and clearing the §2.5
  filter while its field is focused lives here too) > cancels navigation
  (§2.8) > closes
  the Get Info panel (§2.6)
  > clears an active-but-unfocused §2.5 filter (a filter persists
  after its field loses focus, so it needs its own tier — below
  navigation cancel, or Esc during a filtered loading pane would clear
  the filter instead of cancelling) > clears a pending §2.5 type-ahead
  buffer (one press clears the buffer, the next deselects) > deselects.

### 8.4 Quick Open palette

⇧⌘P / Ctrl+Shift+P opens a centered palette over the window (max width
560): one fuzzy-search field over three ranked sections — **Commands**
(enabled ones first, disabled shown greyed with reason tooltip),
**Favorites** (all kinds, with their icon+color badges), **Recent
locations**. Rules, adopting ForkLift's shortcut-teaching loop:

- Command rows show their shortcut, right-aligned, and — only when one
  exists, since §8.1 leaves commands like `view.refresh`,
  `pane.swapFocus`, and `app.quickOpen` shortcut-only — their menu path
  (`Go ▸ Go to Folder…`) as a secondary line; favorite and recent rows
  have no shortcut (nothing binds them in v1 — custom keymaps are
  post-v1, §8.3) and omit the gutter.
- **Pressing a command's bound *modifier-chord* shortcut while the palette
  is open executes it — but only when the command is app-scoped; the scope
  rule below suspends every pane/selection chord** — the palette teaches
  and accepts the fast path — under **one scope rule plus one carve-out**, so a chord's
  palette behavior is mechanically checkable against §8.3. *Scope rule:*
  while the palette holds focus, every pane/selection-scoped command is
  **suspended** — no chord typed in the field executes a file verb over
  the background pane, so ⌥⌘V (`edit.moveHere`), ⌥⌘⌫ / Shift+Delete
  (`file.deletePermanently` — the table's single most destructive verb),
  and every other pane chord simply do nothing there (this replaces
  round-7's "fired over the background pane" framing: the outcome is the
  same, the model is now unambiguous). **App-scoped chords**
  (`pane.focusLeft`/`focusRight`, `tab.close`, the view toggles, and ⇧⌘P
  itself, which toggles the palette) are not suspended by the scope rule,
  so executing any chord from the palette **closes the palette first** —
  no app command ever runs beneath or races the open overlay. *Carve-out:*
  the platform
  text-editing chords keep their field meaning so the query stays a real
  text field — ⌘X/⌘C/⌘V/⌘Z/⌘A, ⌘⌫, the Ctrl-equivalents on Windows/Linux,
  and (macOS end/start-of-field caret chords) ⌘↓/⌘↑, which §8.3 otherwise
  binds to `go.open`/`go.enclosing`. Pasting a host or path into Quick
  Open therefore never executes the file-verb Paste, and no keystroke in
  the field can move or delete the pane's selection — and a chord bound
  to a *disabled* **app-scoped** command (app-scoped chords being the
  only kind eligible to execute from the palette) no-ops: the close-first
  rule guards actual execution only, so the palette stays open and
  surfaces that command's reason tooltip instead of executing; suspended
  pane/selection chords stay silent whether their command is enabled or
  not.
  All of §8.2's unmodified single-key pane bindings (Space, ⏎/Enter,
  Tab, Backspace, F2, F5, F6, Delete, type-ahead — the full §8.2 list,
  not an excerpt; Esc stays bound to closing the palette) are
  suspended while the palette is open; plain keystrokes
  always reach the search field (§8.2's focus scoping already implies
  this — the palette's field has focus — stated here so nobody "helpfully"
  forwards them).
- Enter runs the selected row (a favorite opens per §4 rules, a Recent
  location opens like a favorite, a Command row runs). ⌥⏎/Alt+Enter (open
  in the *other* pane) and ⌘⏎/Ctrl+Enter (open in a new tab) apply to the
  two location-bearing sections — favorites and Recent locations; on a
  Command row, which has no pane/tab target, both collapse to plain Enter
  and run the command — these Enter-family chords are **palette-local**, and the scope
  rule above suspends the pane commands they would otherwise collide with
  (Windows/Linux `file.getInfo` is Alt+Enter in §8.3), so the ⌥ =
  other-pane, ⌘ = new-tab vocabulary matches §4's sidebar clicks on every
  platform and the two surfaces never train opposite muscle
  memory; Esc closes.
- Fuzzy match: subsequence with word-boundary bonus, per section — Command
  rows match on label and menu path (`Go ▸ Go to Folder…`), favorites on
  label, host, and path, and Recent locations on path and host.

## 10. Dialogs and notices

**Top toasts** — port Séance's `top_toast.dart` verbatim (stacking,
root-overlay resolution, reversed dismiss animation, timer ownership).
Top-anchored stands here too: the bottom edge belongs to the activity panel
and status bar. Rules:

- Toasts carry only **transient outcomes**: `Saved and uploaded.`,
  `Workspace "X" opened` (+ Undo), `Copied path`. Default 4 s; action
  toasts 12 s.
- Anything durable goes to a **persistent banner** (Séance's
  `_UpdateBanner` pattern; SEA-039 is the anti-pattern): update available,
  restored-paused queue (§6), sync-account attention needed, OS keyring
  locked (with Retry). Banners render above the panes, are dismissible, and
  persist across navigation until resolved or dismissed.
- Transfer failures live in the activity panel rows (§5.3); a toast may
  summarize, but the panel is the record. Hidden or dishonest transfer
  state is the category's cardinal sin (D16).

**Destructive dialogs quantify what is lost** (Séance's delete-confirmation
pattern — its server delete counts unsaved managed edits):

- Buttons carry verbs, never "OK": `Delete 12 Items`, `Cancel Transfers and
  Quit`. The safe action is the default button. One dialog at a time —
  modals never stack: every dialog flows through a single FIFO modal
  queue — a transfer-conflict dialog raised while another modal shows
  waits its turn with transfers running underneath, nothing is dropped —
  and the quit dialog alone **supersedes** the showing modal rather
  than stacking behind it: it appears immediately; cancelling the quit
  returns the superseded dialog to the head of the queue — and so does
  `Keep Transferring`, which likewise cancels the quit — while
  confirming resolves the queued dialogs concretely: `Pause and Quit`
  leaves each pending transfer-conflict decision paused with its item,
  logged to the activity panel to resolve on next launch, and `Cancel
  Transfers and Quit` dismisses the queued dialogs as moot with their
  tasks — so "jumps the queue" never silently discards a
  pending decision. When the per-server trash option
  is off, `Cancel` is the default button of the remote-delete dialog:
  permanent deletion is never the default action.
- Remote delete (default confirm-then-permanent, D15):
  `Delete 12 items (1.4 GB) from prod-web-01? This cannot be undone.` —
  with names
  listed when ≤ 3, a count and total size otherwise. The quantifying
  walk behind that count (also what detects §13's flagged descendants)
  is cancellable, shows a progress line, and **gives up on a timeout
  or error into the unquantified fallback copy** `Delete the selected
  items from prod-web-01? This cannot be undone.` — except §13's
  flagged-descendant disclosure, which never falls back to silence: the
  counted `includes N items with an undecodable name` rides along when the
  walk's flag pass completed before the timeout, and the hedged `may
  include items with undecodable names` appears when it did not, so an
  ancestor delete never silently removes flagged descendants. §12/P5 bans
  upfront tree stats for transfers precisely because remote walks can
  be slow, and a huge or flaky tree must never keep the destructive
  confirmation from appearing at all. When the per-server
  trash option is enabled, the checkbox `Move to .poltergeist-trash/
  instead` appears **pre-checked** (the server's configured default is the
  default action, so `Move 12 Items` is the default button while checked;
  unchecking it reverts the default button to `Cancel`, since the dialog
  is then a permanent delete), and while checked the whole dialog switches to
  move-wording — the headline reads `Move 12 items (1.4 GB) to
  .poltergeist-trash/ on prod-web-01?` and the confirm verb becomes `Move
  12 Items` (never a delete verb, matching the reversible action) — and the
  warning line reads `Items are
  moved to .poltergeist-trash/ on the server.` with the helper sentence
  `Trashed files stay on the server, readable by anything that can read
  the folder, until you purge them.` — server-side trash is a rename,
  not removal, and on a web-served root the "deleted" file may stay
  fetchable over HTTP, so the copy must not imply safe disposal. The
  copy always matches
  the action about to run, never a scarier one — including the
  unquantified fallback: when the trash checkbox is checked and the walk
  times out, the fallback copy is `Move the selected items to
  .poltergeist-trash/ on prod-web-01?` (still carrying the
  flagged-descendant disclosure), never the delete-worded fallback.
- Permanent local delete: `Permanently delete "report.pdf"? It will skip
  the {Trash|Recycle Bin}.` — the trash noun follows §11's per-platform
  verb table (Trash on macOS/Linux, Recycle Bin on Windows) through the
  ARB catalog, never hardcoded.
- Quit with active transfers: `2 transfers are running (1.2 GB remaining
  so far).` — the remaining figure is the growing-totals floor (§12/P5:
  no upfront tree stat): total discovered so far minus bytes completed, a
  lower bound that never overstates (the known total only grows), so the
  copy says "so far" rather than implying an exact total.
  → `Pause and Quit` (default) / `Cancel Transfers and Quit` / `Keep
  Transferring` (cancels the close). Until resumable transfers ship
  (D25), a paused in-flight file restarts from byte zero on relaunch —
  and the dialog says so: `Files in progress restart from the beginning
  next launch.` (honest copy beats a falsely safe-sounding default; the
  §6 restored-queue banner makes no resumption claim either).
- Editor discard/conflict dialogs are 06's, unchanged from Séance.
- Confirmation logic lives inside the state operation, not at one call
  site (SEA-009 lesson), so every entry point — menu, shortcut, drag —
  gets the same guard.

**Settings** is one screen with five tabs — General / Transfers / Editing /
Sync / Advanced — and this list is the single owner of the settings
surface: every preference this plan names lives in one of these tabs
(03 §6's `SettingsStore` inventory assigns each a storage home), with 06 §8
owning the Editing tab's detail.

## 11. Design language — "quiet chrome" (D11)

The chrome recedes; content (file names, paths, progress) is the interface.
Flutter with a bespoke desktop-density system seeded from Séance's theme
approach — never stock Material-mobile.

- **Theme**: `ColorScheme.fromSeed` per brightness, `useMaterial3`,
  `ThemeMode.system` default with a setting. Poltergeist's seed is its own:
  a muted spectral teal, `0xFF3D8A78` — deliberately distinct from Séance's
  violet so the sibling apps read as family, not clones.
- **Accents**: the `server_appearance.dart` module ported whole — accents
  are `ColorScheme.fromSeed(seed, brightness)` triples, **memoized** on
  `(color, brightness)`; badges compose icon + one status dot ringed in
  surface color; `PositionedDirectional` for RTL. The `ServerColor`/
  `ServerIcon` enums come from `seance_protocol` unchanged (sync-wire
  compatibility, D4).
- **Density**: `VisualDensity.compact` baseline; fixed row extents 28 px
  (comfortable, default) / 22 px (compact, a setting). Controls sized for
  pointer-first use; nothing mobile-padded.
- **Typography**: UI text uses the platform default sans stack. Paths,
  file sizes, permissions, the path-bar editor, and the editor use the
  mono stack from Séance's `theme.dart`: `JetBrains Mono, SF Mono, Menlo,
  Consolas, DejaVu Sans Mono, monospace` (a bare `monospace` family does
  not resolve on Apple platforms). Size and date columns use tabular
  figures so rows align.
- **Iconography**: one outlined icon set (Material Symbols) at 18–20 px,
  single visual weight. File-type icons: the pure-Dart extension→icon map
  as the base layer everywhere; native icons/thumbnails are a later
  per-platform channel behind a seam (03). Remote listings always use the
  base layer.
- **Truncation**: all name/path truncation routes through
  `MiddleEllipsisText` (grapheme-safe, semantics-labeled) — memoized in
  virtualized rows; never ad-hoc `substring` (SEA-006 class).
- **Status colors** are theme-aware and contrast-checked from day one
  (D20; fixes the SEA-019 class rather than porting it).

**Per-platform chrome** — non-negotiable conventions (D11):

## 13. Accessibility and i18n (D20)

Semantics are hand-built for every custom row type; retrofit is expensive,
so these ship with the widgets:

- **File row**: one merged semantics node — `"report.pdf, PDF document,
  12.3 kilobytes, modified today 14:32"` + selected state; actions for
  open/rename exposed — announced as disabled, with the reason, on flagged
  (non-UTF-8-name) rows. Column data is announced in Name-Kind-Size-Date
  order regardless of visual column order — the order the example above
  demonstrates and the 08 semantics test asserts.
- **Column header**: button semantics + sort state (`"Size, sorted
  descending"`).
- **Path segment**: button, `"Go to var"`; the collapsed `…` segment lists
  its menu.
- **Tab**: tab semantics with selected state and a close action.
- **Sidebar group header**: `MergeSemantics` + `Semantics(expanded:)`
  inside the merge, count spelled out — the Séance `server_list_pane.dart`
  standard, kept.
- **Activity row**: label + state; completion and failure announced via a
  live region; progress percent is *not* announced continuously (throttled
  to state changes).
- **Splitters**: focusable, keyboard-resizable (§1), labeled
  (`"Resize sidebar"`) with value announcements.
- **Focus-visible**: a 2 px accent outline on every focusable element,
  never suppressed.
- **Contrast**: text ≥ 4.5:1, indicators and status colors ≥ 3:1 against
  their actual surfaces in both themes; checked by the 08 a11y test over
  an explicit foreground × surface token matrix per theme that includes
  composite surfaces — badges, banners, selected rows, tinted activity
  and plan rows, tooltips — kept in lockstep with the widget inventory
  (a bare token-set check only covers pairs someone remembered to name).
- **Linux honesty**: Flutter's Linux screen-reader support is broken
  upstream (tracked as
  https://github.com/flutter/flutter/issues/95230 — focused widgets not
  announced — and https://github.com/flutter/flutter/issues/101513 —
  the a11y tree breaking for Orca mid-session; verify both IDs' current
  status at every engine upgrade and plan revision, and retire this
  note the release they close); documented plainly in README/docs, not
  papered over.

i18n:

- All user-facing strings in ARB via `gen-l10n` from the first widget;
  English-only at v1 but fully externalized; plurals/dates/numbers via
  `intl`. A lint/test (08) fails on hardcoded literals in `lib/ui` —
  and engine-layer user-facing strings (transfer/sync sub-row labels
  like `Name is not valid UTF-8 — skipped`, failure reasons) are emitted
  as typed reason codes that the UI maps through the ARB catalog, so no
  user-visible sentence is authored outside it.
- **RTL**: layout mirrors under RTL locales (`Directionality`-aware
  spacing, `PositionedDirectional` — already the ported modules' habit).
  Pane commands `focusLeft`/`focusRight` refer to *visual* sides. Paths
  and filenames render inside Unicode directional isolates (LRI/PDI) so
  BiDi filenames cannot reorder path separators. Copied paths and URLs
  (copy-path/copy-URL) are assembled from the model's **logical** path
  string, never from the isolate-wrapped display text — U+2066/U+2069
  controls must never reach the clipboard (08 asserts copied strings
  carry no LRI/PDI characters).
- **Non-UTF-8 filenames**: SFTP names are byte strings; local Linux names
  can be non-UTF-8 too. v1 policy: decode as UTF-8 strictly; on failure
  the entry is flagged and displayed with U+FFFD replacement characters
  plus a warning badge and a tooltip (`Name is not valid UTF-8; shown
  approximately`), and **single-target rename, delete, transfer (as
  source or as destination — nothing may be dropped or pasted *into* a
  flagged folder either), open/preview, and copy-path/copy-URL of such
  entries are blocked** —
  their affordances (context menu, toolbar, drag) render disabled with
  the reason, as the file-row semantics above require for
  open/rename, the explanatory error reserved for invoke paths with no
  pre-disableable affordance; multi-selection deletes, multi-selection
  transfers (drag or copy/paste), and container
  transfers instead skip flagged entries as terminal `skipped` sub-rows
  (below). A lossy display string must never
  round-trip to the wire, the clipboard included (a U+FFFD path pasted
  into a terminal or script is the same wire, one hop later), and
  opening or previewing a remote flagged
  entry would be a transfer by another name. Inside a directory transfer (or sync scan, 05),
  a flagged entry discovered mid-walk becomes a per-file `skipped` sub-row
  (`Name is not valid UTF-8 — skipped`) in the §6 model — a **terminal**
  state with no retry affordance (retry can never succeed) and tallied
  separately from genuine failures; its siblings and
  the rest of the task continue, and the end-of-task toast summarizes the
  skip count — one legacy-encoded name deep in a tree never fails a whole
  drop. Sorting and filtering use the decoded form — decoded-name
  collisions (distinct byte names decoding to identical U+FFFD strings)
  tie-break **deterministically on the raw bytes** so ordering is stable
  across refreshes and virtualization — but by-name matching
  (type-ahead, Quick Select) never targets flagged entries — the same
  U+FFFD collision makes a name match ambiguous — though flagged rows
  **stay selectable** via mouse click and arrow-key focus (the
  multi-selection delete rule below relies on it, so the by-name
  exclusion must not be over-applied to selection); and the file-row semantics (above) announce the
  open and rename actions as disabled on flagged rows rather than
  offering actions that always error. The same U+FFFD collision would
  otherwise let two distinct flagged files look like one indistinguishable
  entry in the itemized skip report — the exact list a user reads to find
  which file needs a workaround — so both the warning tooltip and each
  itemized `skipped` sub-row additionally render a byte-accurate escaped
  form of the raw name (`\xNN` for each undecodable byte) alongside the
  lossy string, distinguishing any two names that collide under lossy
  decoding without needing v1's parked byte-preserving handling to do it.
  The collision is not only flagged-vs-flagged: a flagged name's U+FFFD
  rendering can equal a genuinely valid, fully operable UTF-8 sibling
  whose name legitimately contains U+FFFD — the same raw-byte
  collision-detection the sorting rule above already runs (it must
  already identify every name sharing one decoded string to tie-break
  their order) extends its result to gate the escaped-rendering
  treatment too, so a colliding valid sibling gets the same disambiguating
  `\xNN` form alongside its name wherever the flagged entry appears next
  to it, not only the flagged entry itself.
  Byte-preserving
  operations on non-UTF-8 names (including delete and open — until then
  such entries are removable only via ancestor operations, and openable
  only outside Poltergeist) are
  parked (D25). Ancestor operations are different: deleting or renaming
  a *parent* directory puts only the parent's (valid UTF-8) name on the
  wire, so they proceed — with the confirmation counting and disclosing
  any flagged descendants (`includes 1 item with an undecodable name`),
  never removing them silently under the block policy's nose. A direct
  multi-selection delete or transfer containing flagged entries follows
  the same mid-walk rule as container transfers: flagged items become
  `skipped` sub-rows, the rest complete, and the toast summarizes the
  skips — one legacy name never strands eleven deletable (or
  transferable) siblings — and the pre-operation confirmation discloses
  this up front: it counts only deletable/transferable items in its
  headline and verb, and carries a `1 item with an undecodable name will
  be skipped` line, so the confirmed count always matches what the
  operation will do.
